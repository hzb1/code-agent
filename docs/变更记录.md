# 变更记录

本文件记录本仓库对外可感知的重要变更，重点覆盖：
- 版本发布；
- 能力边界变化；
- 关键重构；
- 文档与版本线收口。

记录原则：
- 优先以 Git tag 和主线提交为依据；
- 不臆造不存在的历史版本；
- 当前从 `v0.1.0` 开始维护正式版本记录。
- 分类口径尽量明确，优先使用以下类型：
  - `Added` / `新增`：新增能力、入口、模块、工具、脚本或文档主项；
  - `Changed` / `变更`：既有能力的行为调整、重构、重命名、默认值更新或架构切换；
  - `Deprecated` / `弃用`：当前仍可使用、但已不再推荐，且将在后续版本移除或替换的能力、接口或入口；
  - `Removed` / `删除`：移除旧能力、旧文档、旧兼容层、废弃入口或无效依赖；
  - `Fixed` / `修复`：明确修复 bug、错误处理缺陷、稳定性问题或兼容性问题；
  - `Security` / `安全`：权限边界、路径校验、危险操作限制、输入校验或其它安全相关修正与增强；
  - `Docs` / `文档`：README、约束、版本计划、注释和说明性文档的显著更新；
  - 如某项变更同时符合多个类别，应优先归入“对用户影响最直接”的那一类，避免重复记录。

格式参考 Keep a Changelog，并结合本项目实际情况以中文维护。


## [Unreleased]

### Added
- 新增 Permission Model（权限模型）三态裁决：`allow` / `ask` / `deny`，并在 `queryLoop` 中于工具执行前统一生效。
- 新增 Plan Mode（计划模式）能力：
  - CLI 单次入口：`ca --plan "<需求>"`
  - REPL 命令：`/plan <需求>`、`/approve`
- 新增 `write_file` 工具：项目边界内安全写文件、覆盖保护、差异预览。
- 新增 `exec_command` 工具：白名单命令执行（`build/typecheck/test/lint`）、超时控制、结果结构化回填。
- 新增权限确认层：`src/cli/confirm.ts` 与 `src/cli/preview.ts`。
- 新增单元与集成测试，覆盖权限三态、计划模式、写入与命令执行关键链路。

### Changed
- `QueryEngine` 增加运行模式状态（`normal / plan / plan-approved`）与最近计划快照管理。
- `Tool Protocol` 扩展 `checkPermissions` 接口，支持工具级权限裁决。
- `npm test` / `npm run test:*` 脚本改为 `--loader tsx`，提升当前 Node 环境兼容性。
- 包版本更新为 `0.3.0`，并同步 README 的能力说明与命令示例。

### Security
- Plan Mode 下所有非只读工具会被系统拒绝，避免未批准状态下误改动。
- `write_file` 对越界路径直接拒绝，并在覆盖前要求明确确认。
- `exec_command` 对非白名单命令直接拒绝，默认不开放任意命令执行。

### Docs
- 新增 `docs/文档中心.md` 作为文档中心，明确仓库入口、规则文档、产品文档、版本计划和变更记录各自的职责。
- 收紧 `README.md`、`产品说明.md` 和 `docs/version-plan/版本总览.md` 的边界，减少“入口说明 / 产品定义 / 版本路线”之间的重复。
- 收口版本类文档，把“版本演进 / 版本速览 / 覆盖承诺”统一合并到 `docs/version-plan/版本总览.md`。

## [0.2.0] - 2026-04-13

### Added
- 增加只读检索工具组，形成 `list_files + search_files + read_file` 的基础代码检索链路。
- 增加 REPL（持续聊天模式），支持多轮追问和基础会话内命令。
- 增加 Session Storage（恢复最近会话）v1，用于保存和恢复最近一次会话。
- 增加 `doctor`（基础诊断命令），用于检查配置、provider 组合和常见排障项。

### Changed
- 将 QueryEngine 从“单次请求编排器”升级为“会话编排器”，开始持有消息状态、会话标识和只读缓存。
- 将仓库对外表述从“早期问答原型”更新为“可运行的只读型 CLI Agent”。

### Docs
- 补充 `v0.2.0` 版本文档的完成状态说明，并将当前能力同步到 README。
- 将版本元数据更新到 `0.2.0`，使版本文档、仓库说明和包版本保持一致。

## [0.1.1] - 2026-04-07

### Added
- 增加骨架级调试事件模型，为 QueryEngine / QueryLoop 的后续观测能力打底。
- 增加最小测试基础设施，覆盖 QueryLoop、QueryEngine 和 CLI 基础链路。
- 增加 `test` 相关脚本，使补丁版本具备稳定回归入口。

### Fixed

- 收口 CLI 错误出口与基础排障文案，提升骨架阶段的稳定性和可诊断性。

### Docs
- 同步补充 `v0.1.1` 的实现范围、调试能力和测试能力说明。

## [0.1.0] - 2026-04-06

### Added
- 增加可运行的本地 CLI 原型，支持通过 `ca` 命令发起单次项目问答。
- 增加 QueryEngine 与 QueryLoop 基础执行链路，形成“用户输入 -> 模型请求 -> 工具执行 -> 最终回答”的最小闭环。
- 增加只读工具系统原型，当前提供 `read_file` 工具，用于在项目根目录内安全读取 UTF-8 文本文件。
- 增加 LLM provider 基础接入能力，当前支持 `qwen`、`zhipu`、`deepseek`、`bytedance`。
- 增加稳定性基础能力，包括超时、重试、限速与更可读的错误提示。
- 增加 HTTP 调试日志输出能力，便于排查请求载荷、响应状态和服务端返回片段。
- 增加 Biome 相关脚本与基础工程命令，包含 `build`、`typecheck`、`lint`、`format`、`dev`、`start` 等常用入口。
- 增加 `CONSTRAINTS.md`、`AGENTS.md` 与 `docs/version-plan/`，用于约束工程边界、代理协作方式与版本推进路线。

### Changed
- 将 CLI 命令入口统一调整为 `ca`，并同步更新 README 中的运行方式说明。
- 将 CLI 和运行时主要提示文案本地化为中文，降低当前阶段的理解和排障成本。
- 重构查询主流程，引入更清晰的消息模型、错误类型与循环职责分层。
- 移除早期过渡性质的 `runAgent` shim 与 `core types shim`，收敛到当前的 QueryEngine / QueryLoop 架构。

### Docs
- 明确项目正式目标不再停留于 `read_file` Demo，而是逐步演进为与本地参考项目同类的 CLI Coding Agent。
- 补充版本计划、覆盖矩阵与 README 使用说明，定义 `0.x.0` / `0.x.1` 的版本推进策略。
- 强化代码注释与设计说明，提升当前原型阶段的可读性和可维护性。
