# 学习路线

## 目标与范围
通过亲自实现一个本地 CLI Coding Agent（命令行编码智能体），掌握消息、工具、循环、状态、安全和上下文等核心边界。

路线按知识依赖组织，不使用产品版本号衡量学习进度。当前采用“核心主线优先”：详细规划入门诊断和 8 个核心主题，扩展能力等核心系统完成后再学习。

## 学习优先级
投入最多时间的四个主题是：
1. `Tool Protocol（工具协议）`
2. `Agentic Loop（智能体循环）`
3. `QueryEngine（会话编排器）`
4. `Permission Model（权限模型）`

它们共同决定 Agent 如何行动、如何循环、谁持有状态，以及怎样控制危险副作用。

## 0. 入门诊断：CLI 输入与输出
- **定位**：快速确认 Node.js CLI 基础；会就直接通过，不扩展为长期课程。
- **前置知识**：基础 TypeScript、Node.js 程序运行方式。
- **核心问题**：`process.argv` 如何承载输入；`stdout`、`stderr` 和退出码分别表达什么；参数校验属于哪一层。
- **实践产物**：可接收并回显输入、拒绝空输入的 CLI，以及正常与失败路径测试。
- **参考源码**：不阅读 `claude-code-fork`，先独立完成。
- **完成标准**：能处理单参数、多参数、空输入和多余空格，并解释输出通道与退出码的选择。

## 1. 最小模型调用
- **重要性**：先看到真实的 LLM 调用闭环，后续抽象才有具体对象。
- **前置知识**：通过 CLI 入门诊断。
- **核心问题**：模型配置如何校验；HTTP 请求和响应包含什么；超时、网络错误和不可读响应如何处理。
- **实践产物**：跑通“用户输入 → 配置校验 → 模型请求 → 模型回答 → CLI 输出”。
- **参考源码**：只阅读与一次模型请求直接相关的 API 服务代码，不读取 Engine、工具和循环实现。
- **完成标准**：能独立发起请求、解释请求与响应结构，并亲自定位一个配置或网络失败。
- **主动省略**：`QueryEngine`、工具调用、多 Provider、完整重试和会话保存。

## 2. 消息模型与 Provider 边界
- **重要性**：消息是模型、工具、会话和上下文之间共同流动的数据；Provider 边界防止 Agent 核心绑定第三方格式。
- **前置知识**：完成最小模型调用。
- **核心问题**：内部 `Message` 表达什么；为什么不能直接使用第三方请求结构；转换、请求和错误分别属于哪一层。
- **实践产物**：内部消息类型和单一 Provider 转换边界，CLI 与 Agent 核心不感知第三方字段。
- **参考源码**：`src/services/api/openai/*` 及消息转换相关实现。
- **完成标准**：能画出内部消息到外部请求再返回内部结果的数据流，并完成一种响应变化的适配。

## 3. Tool Protocol（工具协议）
- **重要性**：它决定检索、写入和命令工具能否通过统一边界扩展，是最高优先级主题之一。
- **前置知识**：掌握消息模型和 Provider 边界。
- **核心问题**：模型如何发现工具；名称、描述、输入 Schema 和执行函数如何组织；校验与结果如何统一；注册表为什么独立。
- **实践产物**：统一工具接口、工具注册入口和一个最小只读工具。
- **参考源码**：`src/Tool.ts`、`src/tools.ts`。
- **完成标准**：能独立新增第二个工具而不修改协议核心，并覆盖正常输入、非法输入和执行失败。

## 4. Agentic Loop（智能体循环）
- **重要性**：Coding Agent 的执行发动机，是整条路线投入最高的主题。
- **前置知识**：掌握消息模型、Provider 边界和工具协议。
- **核心问题**：工具请求和结果如何对应；循环何时继续、结束或失败；工具失败如何处理；怎样避免无限循环。
- **实践产物**：可完成普通回答、单次工具调用和连续工具调用的 `QueryLoop`。
- **参考源码**：`src/query.ts`。
- **完成标准**：能脱离参考实现画出状态流，并测试普通回答、工具成功、工具失败和循环超限。

## 5. QueryEngine（会话编排器）
- **重要性**：把单轮循环放进长期会话，明确状态所有权，避免下层隐式修改上层状态。
- **前置知识**：完成 `QueryLoop`。
- **核心问题**：Engine 与 Loop 如何分工；谁拥有消息历史；为什么传递消息快照；一轮失败后保留什么。
- **实践产物**：`QueryEngine` 管理多轮会话，`QueryLoop` 只执行单轮循环。
- **参考源码**：`src/QueryEngine.ts`，并与 `src/query.ts` 对照。
- **完成标准**：能完成多轮追问，证明输入没有被原地修改，并处理一次单轮失败后的状态。
- **主动省略**：会话持久化、完整 REPL 和后台会话。

## 6. 只读项目工具与路径安全
- **重要性**：把工具协议和 Agentic Loop 迁移到真实代码库理解场景。
- **前置知识**：完成工具协议、Agentic Loop 和 QueryEngine。
- **核心问题**：如何限制项目边界；如何处理路径穿越、软链接、超长文件和过多结果；三个工具怎样分工。
- **实践产物**：依次实现 `list_files`、`search_files`、`read_file`，跑通“搜索 → 读取 → 回答”。
- **参考源码**：对应只读工具及路径处理代码，只提取当前三个工具需要的边界。
- **完成标准**：能处理正常读取、非法路径、结果截断和软链接风险，并解释限制应放在哪一层。

## 7. Permission Model（权限模型）与受控执行
- **重要性**：Coding Agent 会产生真实副作用，权限必须成为系统能力，不能只依赖提示词。
- **前置知识**：已有稳定的工具协议和只读工具链路。
- **核心问题**：`allow / ask / deny` 如何定义；权限与执行为什么分离；拒绝如何回填；Plan Mode 如何限制执行；怎样限制写入和命令。
- **实践产物**：按“权限模型 → 计划与确认 → `write_file` → `exec_command`”的顺序完成受控执行闭环。
- **参考源码**：权限判断、计划模式、文件修改和命令执行相关实现，重点比较安全边界。
- **完成标准**：测试允许、确认、拒绝、拒绝回填、路径越界、命令拒绝和超时，并能说明危险副作用经过的权限路径。

## 8. Context System（上下文系统）与核心收口
- **重要性**：上下文决定模型看见什么；核心收口验证前面各层能否形成可持续使用的整体。
- **前置知识**：完成会话编排、只读工具和受控执行。
- **核心问题**：规则、消息、历史和工具结果如何排序；信息属于项目、会话还是当前轮次；如何裁剪；如何统一流式事件和诊断。
- **实践产物**：统一上下文构建与核心流式事件，完成涵盖读取、计划、确认、修改和验证的端到端测试。
- **参考源码**：`src/context.ts`、流式适配和调试事件相关代码。
- **完成标准**：能解释一次请求的完整上下文来源，处理一次裁剪变化，并根据事件或错误定位端到端失败。
- **主动省略**：打字机动画和非核心视觉效果。

## 后续方向
核心主线完成后，再按需要学习：会话持久化、完整 REPL、多 Provider、MCP、Skills、后台会话、子 Agent、工作树隔离、发布工程。

这些方向当前只保留名称，不提前设计接口或目录。

## 所有主题统一完成证据
1. **解释**：能用自己的话说明端到端流程、职责和设计原因。
2. **实现**：能在没有现成答案的情况下完成核心行为。
3. **调试**：能根据现象、假设和证据定位至少一个失败。
4. **变化练习**：能处理一个新条件，并判断应该修改哪一层。

构建和测试通过是必要条件，但不能单独证明已经掌握。
