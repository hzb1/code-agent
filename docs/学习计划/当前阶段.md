# 当前阶段：入门诊断——CLI 输入与输出

## 阶段定位
本阶段只用于确认 Node.js CLI 基础是否足够进入 Agent 核心主线。已经掌握就快速完成，不扩展架构，不阅读参考项目，也不把投入时间作为学习成果。

## 本阶段只学一个问题
一个 Node.js CLI 程序如何接收用户输入、校验输入、选择输出通道，并用退出码表达成功或失败？

## 开始前先回答
暂时不要查看旧实现或参考项目，先写下自己的判断：
1. `npm run start -- "你好"` 中的“你好”从哪里进入程序？
2. `process.argv[0]`、`process.argv[1]` 和后续元素通常分别是什么？
3. 没有输入时应该写入 `stdout` 还是 `stderr`？退出码应该是什么？
4. 参数解析属于 CLI 层还是未来的 Agent 核心层？为什么？

## 由学习者完成
修改 `src/cli/index.ts`：
- 读取用户参数并形成一段输入；
- 明确定义多参数和多余空格的处理规则；
- 拒绝空输入，在正确输出通道显示清楚的中文用法；
- 输入有效时原样输出，暂时不调用模型；
- 为正常输入、多个参数和空输入编写测试。

## 本阶段暂时不做
- 不读取模型环境变量；
- 不调用 LLM；
- 不设计 `Message`、`QueryEngine`、`QueryLoop` 或工具协议；
- 不读取 `claude-code-fork`；
- 不从 Git 历史恢复旧实现。

## 验证命令
```bash
npm run build
npm run typecheck
npm run test
npm run start -- "你好"
```

还应手动验证空输入时的错误提示和非零退出码。

## 通过条件
只有同时满足以下条件才进入“核心主题 1：最小模型调用”：
- 能独立读取并解释 `process.argv`；
- 能处理单参数、多个参数和多余空格；
- 能正确区分 `stdout` 与 `stderr`；
- 空输入会得到清晰提示和非零退出码；
- 正常与失败路径都有测试；
- 能说明为什么此时不需要 Agent 架构。
