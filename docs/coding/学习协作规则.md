# 学习协作规则

## 1. 目标
本项目的学习目标不是把参考源码重新输入一遍，而是逐步获得四种能力：
1. **解释**：能说明端到端流程、职责划分和设计原因。
2. **实现**：在有限提示下写出核心行为。
3. **调试**：能基于现象、假设和证据定位至少一个失败。
4. **迁移**：条件变化后，能判断应该修改哪一层并完成调整。

只有四项都有证据，一个主题才算学会。构建或测试通过只是产品验证，不等于学习完成。

## 2. 四种协作模式
- `Learn（学习）`：新的核心主题。学习者预测并实现，AI 提问、提示和审查。
- `Pair（结对）`：概念已经理解，但集成工作较大。双方明确拆分所有权。
- `Delegate（委托）`：已经掌握的内容、机械工作，或用户明确要求 AI 直接完成。
- `Review（审查）`：AI 检查学习者的方案或代码，除非明确要求，否则不修改。

默认不能把学习任务静默切换成委托任务。模式变化时应说明原因。

## 3. 渐进帮助等级
| 等级 | AI 可以提供的帮助 |
| --- | --- |
| `H0` | 要求学习者独立尝试 |
| `H1` | 提出聚焦问题，指出需要思考的概念 |
| `H2` | 给出方向提示，指出可能出错的层 |
| `H3` | 给出函数签名、不变量、TODO 骨架或伪代码 |
| `H4` | 给出不直接解决生产任务的最小示例 |
| `H5` | 用户明确要求，或低等级帮助仍无法推进时给出完整方案 |

从最低可推进的等级开始，每次只提高一级。使用 `H5` 不代表失败，但意味着该主题之后需要再做一次脱离答案的复现。

## 4. 一个学习切片
每次只学习一个核心问题和一个可观察行为：
1. **定义结果**：说明本轮问题、成功标准和学习者所有权。
2. **先预测**：在看参考实现前，预测数据流、职责、状态所有权、终止条件和风险。
3. **查证参考**：只阅读与问题直接相关的参考源码，记录预测与实际差异。
4. **独立实现**：关闭或离开答案，根据行为要求重新实现。
5. **加入变式**：修改一个条件，例如超时、取消、工具失败或非法输入。
6. **调试失败**：先观察，再提出假设，用测试、日志或最小复现收集证据，最后修复。
7. **迁移到项目**：提交文件、职责、风险和验证计划，再修改生产代码。
8. **复述总结**：不看代码说明流程、关键不变量、最大风险、与参考实现的差异。

## 5. 所有权划分
新的核心主题中，学习者优先负责：
- 一个核心类型或协议；
- 主流程或关键状态变化；
- 一个失败路径；
- 一个正常路径测试和一个失败路径测试。

AI 可以承担：
- 工程脚手架和重复配置；
- 已经理解后的机械性代码；
- 格式化、文档链接同步和重复测试数据；
- 根据学习者方案做代码审查。

## 6. 每轮结束记录
学习总结保持简短，但至少包含：
- 本轮核心问题；
- 使用过的最高帮助等级；
- 解释、实现、调试、迁移四项证据；
- 尚未掌握的缺口；
- 下一次脱离答案的复现题。
