# 文档中心

## 目的
这份文档只做一件事：
帮助你快速判断“现在该看哪份文档”，避免在多个 `.md` 文件之间来回跳。

---

## 文档分层
### 1. 仓库入口
- [README.md](../README.md)

负责：
- 仓库入口说明
- 当前状态
- 快速开始
- 常用命令
- 调试与排障

不负责：
- 写硬约束
- 写产品定义
- 写每个版本做什么

### 2. 规则与协作
- [CONSTRAINTS.md](../CONSTRAINTS.md)
- [AGENTS.md](../AGENTS.md)
- [docs/coding/AI高风险编码规则.md](./coding/AI高风险编码规则.md)

负责：
- 硬约束
- AI 代理执行方式
- 高风险编码规则

### 3. 产品定义
- [产品说明.md](./产品说明.md)

负责：
- 项目到底在做什么产品
- 为什么做
- 目标用户是谁
- 产品原则是什么

不负责：
- 逐版本开发任务
- 具体实现步骤

### 4. 版本计划
- [docs/version-plan/README.md](./version-plan/README.md)
- [docs/version-plan/覆盖矩阵.md](./version-plan/覆盖矩阵.md)
- `docs/version-plan/v*.md`

负责：
- 版本路线
- 覆盖承诺
- 每个版本做什么
- 每个版本能学到什么
- 当前目标版本的执行依据

### 5. 版本记录
- [变更记录.md](./变更记录.md)

负责：
- 已经发布或收口过的版本记录
- 重要能力变化
- 对外可感知的文档和架构变化

## 推荐阅读顺序
### 新加入项目的人
1. [README.md](../README.md)
2. [产品说明.md](./产品说明.md)
3. [docs/version-plan/README.md](./version-plan/README.md)
4. 当前目标版本文档
5. [变更记录.md](./变更记录.md)

### AI / Codex 开始执行任务前
1. [CONSTRAINTS.md](../CONSTRAINTS.md)
2. [AGENTS.md](../AGENTS.md)
3. [docs/version-plan/README.md](./version-plan/README.md)
4. 当前目标版本文档
5. [产品说明.md](./产品说明.md)
6. 必要时再读参考仓库源码

### 只想回顾某个版本
1. [变更记录.md](./变更记录.md)
2. 对应版本文档，例如 `docs/version-plan/v0.2.0.md`
3. 如果需要，再回看 [README.md](../README.md)

## 文档命名约定
- 普通说明类文档，优先使用中文文件名。
- 约定型文件名默认保留：
  - 根目录和目录级 `README.md`
  - `AGENTS.md`
  - 版本文档 `v0.x.y.md`
- 这条规则的目的不是追求“全部中文”，而是兼顾：
  - 中文可读性
  - 工具识别
  - 目录入口习惯
  - 版本文档排序与检索稳定性

当前建议：
- 可逐步中文化的通常是：普通说明文档、专题文档、补充文档。
- 需要谨慎保留英文名的通常是：入口文档、代理约定文档、按版本号排序的版本文档。

## 当前建议
- 日常了解项目：先看 `README.md`
- 讨论产品方向：看 `产品说明.md`
- 开发前确认本轮边界：看当前目标版本文档
- 需要知道“哪些规则不能碰”：看 `CONSTRAINTS.md`
- 需要知道 AI 应该怎么做：看 `AGENTS.md`
