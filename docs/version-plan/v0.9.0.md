# v0.9.0

## 版本性质
主版本。

## 版本定位
这是“发布候选版”。

前面的版本已经把核心产品能力和高级系统能力都做进来了，这一版的重点不是再继续长功能，而是让产品达到稳定交付、可回归、可诊断、可发布的状态。

## 本版目标
完成四组工程化工作：
- 自动化测试体系；
- 结构化日志与观测；
- 完整 doctor / debug / 错误诊断；
- 发布与安装流程。

## 为什么这版不是补丁版
因为这里补的不是“小修小补”，而是整套产品工程化底盘。

如果没有这一版，前面的能力再多，也仍然只是“你自己能跑”的系统，而不是“可以稳定交付”的产品。

## 对齐参考仓库的重点
重点参考：

- `claude-code-fork/package.json`

## 本版要做什么
### 1. 建立测试分层
新增：
- `tests/unit/`
- `tests/integration/`
- `tests/e2e/`

覆盖目标：
- QueryLoop；
- QueryEngine；
- Tool System；
- Permission；
- Context；
- REPL；
- 后台会话；
- 子 Agent；
- Provider adapters。

### 2. 升级观测系统
新增：
- `packages/core/src/observability/logger.ts`
- `packages/core/src/observability/events.ts`
- `packages/core/src/observability/trace.ts`

要求：
- 支持模块级 debug；
- 支持事件追踪；
- 支持关键错误分类。

### 3. 升级 `doctor`
要求至少检查：
- 配置完整性；
- provider 联通性；
- session 目录与权限；
- MCP / Skills 可用性；
- 最近错误摘要；
- 关键命令依赖。

### 4. 建立发布流程
新增：
- `scripts/check.sh`
- `scripts/release.sh`
- `docs/release.md`

目标：
- 能跑最小回归；
- 能打包；
- 能生成安装说明；
- 能给试用者分发 CLI 版本。

## 本版结束后的产品状态
- 这是第一版可以作为稳定产品对外试用的版本；
- 你已经具备“发现问题、复现问题、定位问题、回归验证、重新发布”的完整闭环；
- `1.0.0` 只剩最后的总收口与定义。

## 是否已可用
- 对你自己：完全可用。
- 对小范围外部用户：可以。
- 对更广泛用户：接近可用。

## 本版主要学习目标
- 理解为什么工程化不是附属工作，而是产品完成度的一部分；
- 学会给复杂系统建立回归和诊断能力；
- 学会从“自己写着玩”切换到“准备交付别人用”。

## 本版不要做什么
- 不新增新的产品能力边界；
- 不做桌面端；
- 不做云端 SaaS；
- 不做市场和商业系统；
- 不做外围实验功能堆叠。
