# 版本总览

## 这份文档是干什么的
这份文档是本项目唯一的版本总览文档。

它统一回答这些问题：
- 这个项目现在走到了哪一步；
- 每个版本已经做成了什么；
- 下一版要做什么；
- 每个版本的重点是什么；
- 这条路线是否真的覆盖了参考项目最重要的能力与知识点。

它替代了此前分散的几类版本说明：
- 对外展示的“版本演进”
- 内部开工用的“版本速览”
- 覆盖检查用的“覆盖矩阵”

如果要看某一版的详细任务拆解、目录演进和开发清单，再进入对应的 `v0.x.y.md`。

---

## 当前处于什么阶段
当前版本：`v0.0.0` `🌱`

当前产品状态：
- 旧产品实现已经从当前工作树清理，Git 历史仍可追溯；
- 当前只保留可构建的 TypeScript CLI 工程壳和学习文档；
- 下一步从 `v0.1.0` 开始，逐层学习并重建核心骨架。

一句话理解：
> 当前不是产品可用版本，而是为了真正掌握 Agent 架构建立的学习起点。

## 目标版本说明

以下内容描述每个版本计划达到的结果，不代表当前工作树已经完成。完成状态应在学习者通过实现、调试和迁移验证后逐版更新。

### `🚩 v0.1.0`：架构骨架起点
这一版的目标不是堆功能，而是把项目从“能跑的原型”重构成“能继续长的产品骨架”。

这一版计划做成：
- 拆出 `QueryEngine（会话编排器）`
- 拆出 `QueryLoop（单轮智能体循环）`
- 建立统一 `Tool Protocol（工具协议）`
- 建立统一消息模型和基础错误模型
- 打通“用户输入 -> 模型请求 -> 工具执行 -> 最终回答”的最小闭环

这一版的意义：
- 项目第一次有了清晰分层
- 后面新增能力不需要继续堆在一个入口文件里
- 为后续 REPL、权限系统、上下文系统打下骨架基础

### `🚩 v0.1.1`：骨架稳固版
这一版不加新能力，专门把 `v0.1.0` 的骨架打牢。

这一版计划做成：
- 收口核心类型与协议边界
- 收口配置错误、Provider（模型提供方）错误、工具错误、循环终止错误
- 增加骨架级调试事件
- 建立最小测试基础设施
- 收口 CLI 错误出口和文档说明

这一版的意义：
- 骨架从“结构初步正确”进入“可以继续开发”状态
- 后续加功能时，不再完全依赖手工试跑
- 排障、测试和文档开始跟上代码演进

### `🚩 v0.2.0`：只读型 CLI Agent 基础版
这是项目第一次真正具备“对外能解释清楚自己是什么”的版本。

这一版计划做成：
- 增加只读检索工具三件套：
  - `list_files`
  - `search_files`
  - `read_file`
- 增加 REPL（持续聊天模式）
- 增加多轮会话能力
- 增加 Session Storage（恢复最近会话）
- 增加 `doctor`（基础诊断命令）
- 建立更完整的测试覆盖与调试入口

这一版的意义：
- 产品第一次从“单次问答”升级为“能持续追问的代码助手”
- 用户可以不只问一个文件，而是先找代码，再读代码，再继续追问
- 会话不再是一次性，用完即失

这一版本完成后用户可以做的事：
- 问“这个项目是做什么的”
- 找“入口文件在哪”
- 继续追问某个模块怎么工作
- 退出后恢复最近一次会话
- 用 `doctor` 排查基础配置问题

### `🚩 v0.2.1`：只读可用版
这一版计划完成只读阶段的稳定化收口。

这一版计划做成：
- 调整循环上限默认值和提示文案，降低“未收敛就中断”的误报；
- 优化 REPL 与调试输出，提升用户可读性；
- 引入 Biome（格式化 + lint）与导入路径统一规则；
- 补齐只读链路的测试与文档一致性。

这一版的意义：
- 只读链路从“可运行”进入“可持续试用”阶段；
- 为 v0.3.0 危险能力接入留出稳定底座。

### `🚩 v0.3.0`：受控执行版
这一版计划把“规划、权限、执行”三件事首次打通。

这一版计划做成：
- 增加 Permission Model（`allow / ask / deny`）；
- 增加 Plan Mode（`ca --plan`、REPL `/plan`、REPL `/approve`）；
- 增加 `write_file` 与 `exec_command` 工具；
- 增加执行前预览与用户确认流程；
- 增加相关单测与集成测试，覆盖关键安全边界。

这一版的意义：
- 产品正式从“只读助手”升级为“可控执行 Agent”；
- 危险能力不再靠提示词约束，而是进入系统化流程。

## 后续版本
### `🚩 v0.3.1`：受控执行稳定版
重点不是继续加新能力边界，而是把 v0.3.0 的执行链路做稳。

重点会放在：
- 权限确认交互优化；
- `write_file` / `exec_command` 失败回填质量；
- Plan Mode 与执行模式切换体验；
- 相关测试、文档和排障闭环。

对外可以期待：
> `v0.3.1` 之后，这个项目会进入“安全改动可用”阶段。

## 覆盖承诺
这条版本路线的目标不是“看起来像参考项目”，而是确保走完整条路线后：
- 真的学会参考项目最重要的架构与设计思想；
- 真的做出一个完整可用的本地 CLI Coding Agent；
- 真的具备继续向 Codex / Claude Code 同类产品演进的能力。

这里的“全覆盖”指：
- 参考项目的核心产品骨架要覆盖；
- 参考项目的核心执行链路要覆盖；
- 参考项目的核心安全模型要覆盖；
- 参考项目的核心上下文与 provider 设计要覆盖；
- 参考项目里支撑长期使用的工程化能力要覆盖。

| 同类 CLI 产品完成版 | `v1.0.0` | 可长期使用、可交付、可扩展、可继续演进 |

### 不作为 `1.0.0` 阻塞项的内容
这些内容即使参考仓库里出现，也不应阻塞 `1.0.0`：
- Voice
- Computer Use
- Chrome / browser automation 的完整产品化
- 企业级 telemetry / GrowthBook / Sentry 平台化接入
- 云端多用户后台服务
- 非 CLI 形态的完整桌面端产品
