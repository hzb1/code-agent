# v0.0.2

## 版本定位
这是第一个真正动骨架的版本。

目标不是增加用户可见新功能，而是把项目从“一个小 CLI 脚本”重构成“能继续长大的 Agent 骨架”。

## 本版目标
建立最小的 Claude Code 风格结构：
- Entrypoint
- QueryEngine
- QueryLoop
- Tool Protocol
- Message Types

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/entrypoints/cli.tsx`
- `claude-code-fork/src/main.tsx`
- `claude-code-fork/src/QueryEngine.ts`
- `claude-code-fork/src/query.ts`

本版不追求它的复杂度，只学习它的“角色拆分”。

## 本版要做什么
### 1. 增加 `QueryEngine`
新建：`src/app/queryEngine.ts`

职责：
- 接收用户输入；
- 维护一轮执行需要的上下文；
- 调用 `queryLoop`；
- 作为未来多轮会话的承接点。

### 2. 将 `runAgent.ts` 重构为 `queryLoop.ts`
建议新建：`src/loop/queryLoop.ts`

职责：
- 只负责单轮循环；
- 不再直接承担“会话编排”语义；
- 不再作为未来 REPL 的直接入口。

### 3. 定义统一消息类型
新建：`src/core/message.ts`

建议最小类型：
- `SystemMessage`
- `UserMessage`
- `AssistantMessage`
- `ToolMessage`
- `Message`

### 4. 定义统一工具协议
新建：`src/tools/types.ts`

建议最小字段：
- `name`
- `description`
- `inputSchema`
- `execute`
- `isReadOnly`
- `isDestructive`
- `isConcurrencySafe`

### 5. 调整 CLI 入口
`src/cli/index.ts` 不再直接依赖旧的“runAgent 整体逻辑”，而是调用 `QueryEngine`。

## 关键代码任务
- 从旧 `runAgent.ts` 提炼 message 组装逻辑；
- 从旧 `runAgent.ts` 提炼 tool call 解析逻辑；
- 让 `QueryEngine` 只依赖 `queryLoop()`，不依赖具体工具实现；
- 让工具注册中心开始返回统一 Tool 类型。

## 本版结束后的产品状态
用户体验变化很小，但内部结构会出现第一次质变：
- 外壳和循环开始分开；
- 后续 REPL、多轮会话、权限系统终于有地方接入；
- 项目从“可运行 demo”变成“可演进骨架”。

## 本版主要学习目标
- 学会“单轮”和“会话”不是一回事；
- 学会 CLI 入口只是入口，不该承载业务；
- 学会 Tool Protocol 先于 Tool 数量。

## 本版不要做什么
- 不加 `list_files`；
- 不加 `search_files`；
- 不加 REPL；
- 不加流式输出；
- 不做权限系统。
