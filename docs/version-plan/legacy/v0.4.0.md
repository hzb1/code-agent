# v0.4.0

## 版本定位
这是“单包项目开始长成系统工程”的版本。

当 QueryEngine、Loop、Tools、Permissions、Context、Streaming 都逐步成型后，单一 `src/` 目录的边界会越来越模糊。这一版要做的是结构再分层。

## 本版目标
进行 core 抽离与包结构升级，让项目从“一个仓库里的一个程序”演进为“有核心库和入口层的工程”。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/entrypoints/cli.tsx`
- `claude-code-fork/src/main.tsx`
- `claude-code-fork/src/QueryEngine.ts`
- `claude-code-fork/src/query.ts`

本版重点学“角色分层”和“依赖边界”，不是照搬参考仓库的目录名。

## 本版要做什么
### 1. 抽离核心运行层
建议新建：
- `packages/core/`
- `packages/cli/`

其中：
- `packages/core` 放 QueryEngine、Loop、Tool System、Permissions、Context；
- `packages/cli` 放 REPL、输出渲染、doctor、confirm、preview。

### 2. 重新组织目录边界
建议形态：
```text
packages/
├─ core/
│  └─ src/
│     ├─ app/
│     ├─ loop/
│     ├─ tools/
│     ├─ permissions/
│     ├─ context/
│     ├─ prompt/
│     ├─ llm/
│     └─ core/
└─ cli/
   └─ src/
      ├─ entrypoints/
      ├─ repl/
      └─ render/
```

### 3. 抽离公共类型和错误
像这些应沉到 core：
- message types
- tool types
- permission types
- provider contracts
- errors

### 4. 让 CLI 只做“壳”
CLI 不再知道太多业务细节，而是：
- 初始化运行环境；
- 调用 core 暴露的接口；
- 渲染输出；
- 处理终端交互。

## 关键代码任务
- 调整 import 路径，避免循环依赖；
- 抽出 core public API；
- 明确哪些类型可以跨包暴露，哪些不暴露；
- 让构建脚本支持多包或 workspace。

## 本版结束后的产品状态
- 项目不再只是“代码越来越多的单包 CLI”；
- 有了真正的“核心运行层”和“终端壳层”；
- 为后续接桌面端、后台进程、远程模式准备了更健康的边界。

## 本版主要学习目标
- 理解项目结构何时该升级；
- 学会抽离 stable core；
- 学会控制依赖方向，而不是放任模块互相引用。

## 本版不要做什么
- 不做大而全 monorepo 基建；
- 不做桌面端；
- 不做 npm 发布流程；
- 不做插件市场；
- 不做过度抽象。
