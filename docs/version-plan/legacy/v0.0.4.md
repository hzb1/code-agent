# v0.0.4

## 版本定位
这是“读懂代码库”的第一版能力增强。

在参考项目里，`Read / Glob / Grep` 是最基础也最高频的工具组合。你的项目也必须尽快具备这一层能力。

## 本版目标
从“只能读某个具体文件”升级为“能找文件、能搜代码、能再读取”。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/tools.ts`
- `claude-code-fork/docs/tools/what-are-tools.mdx`
- `claude-code-fork/docs/tools/search-and-navigation.mdx`

## 本版要做什么
### 1. 新增 `list_files`
用途：
- 列目录；
- 帮模型理解项目结构；
- 支持入口定位、模块定位。

### 2. 新增 `search_files`
用途：
- 在项目内按关键词搜索；
- 返回候选路径与摘要；
- 为后续 `read_file` 提供定位依据。

### 3. 升级 Tool Registry
工具不再只是“注册后能调”，而是要支持：
- 按名称查找；
- 返回工具列表给模型；
- 区分只读工具和后续危险工具。

### 4. 增加 `doctor` 命令
新建：`src/cli/doctor.ts`

它不是参考项目照搬，而是为当前阶段稳定性服务。至少检查：
- API key 是否存在；
- provider/base URL/model 是否合理；
- cwd 是否正确；
- 网络 / DNS / 429 建议。

## 关键代码任务
- `list_files` 要有限制：深度、数量、路径边界；
- `search_files` 要有限制：结果数、摘要长度、忽略目录；
- `read_file`、`list_files`、`search_files` 都应标记为 `isReadOnly = true`；
- query loop 需要支持“先搜后读再答”的多步只读链路。

## 本版结束后的产品状态
产品第一次具备“项目级理解”雏形。

用户可以开始问：
- 入口文件在哪；
- 某逻辑在哪；
- 某模块怎么组织。

## 本版主要学习目标
- 理解工具不是越多越好，而是先有一个高频核心集；
- 理解工具组合是如何让 AI 从“猜”变成“查”。

## 本版不要做什么
- 不加 `write_file`；
- 不加 `exec_command`；
- 不加 REPL；
- 不加权限弹窗；
- 不加流式输出。
