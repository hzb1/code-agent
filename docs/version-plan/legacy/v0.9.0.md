# v0.9.0

## 版本定位
这是“把产品从开发态推向发布态”的版本。

前面已经有了核心能力和高级能力，这一版的重点不再是加大功能，而是让产品可靠、可诊断、可测试、可发布。

## 本版目标
建立工程化与观测体系，实现：
- 更完整的自动化测试；
- 更强的 doctor / debug / 日志能力；
- 更清晰的错误模型；
- 基础发布与分发能力。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/README.md`
- `claude-code-fork/package.json`
- `claude-code-fork/docs/`

本版重点学“成熟工程能力”，不追求企业级平台化。

## 本版要做什么
### 1. 建立测试分层
建议新增：
- `tests/unit/`
- `tests/integration/`
- `tests/e2e/`

建议覆盖：
- QueryLoop；
- QueryEngine；
- Tool System；
- Permission；
- Context；
- CLI smoke tests。

### 2. 升级诊断命令
`doctor` 要升级为真正的系统检查入口，至少检查：
- 配置完整性；
- provider 联通性；
- session 目录状态；
- 文件权限；
- 可选工具来源；
- 最近错误摘要。

### 3. 建立结构化日志与调试开关
建议新增：
- `packages/core/src/observability/logger.ts`
- `packages/core/src/observability/events.ts`
- `packages/core/src/observability/trace.ts`

### 4. 建立发布基础
建议新增：
- `scripts/release.sh`
- `scripts/check.sh`
- `docs/release.md`

目标：
- 能打包；
- 能跑 smoke check；
- 能给自己发布一个可安装 CLI 版本。

## 建议目录形态
```text
packages/
├─ core/
├─ cli/
└─ shared/

tests/
├─ unit/
├─ integration/
└─ e2e/

scripts/
└─ release.sh
```

## 关键代码任务
- 测试不要只测 happy path；
- 错误对象要有分类和上下文；
- debug 输出要能按模块筛选；
- 发布前要有最小回归脚本。

## 本版结束后的产品状态
- 项目从“自己能跑”进入“可以稳定交付”阶段；
- 排障、回归、发布都开始变得有章可循；
- 1.0.0 前的工程准备基本就绪。

## 本版主要学习目标
- 理解成熟产品为什么必须有诊断和回归能力；
- 理解测试不是附属物，而是架构稳定性的保险；
- 学会把“开发方便”升级为“交付可靠”。

## 本版不要做什么
- 不做复杂云端 observability 平台；
- 不做营销官网；
- 不做团队权限中心；
- 不做商业授权系统；
- 不做跨平台安装器矩阵。
