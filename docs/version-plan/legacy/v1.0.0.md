# v1.0.0

## 版本定位
这是“参考项目同类 CLI 产品完成版”。

这里的“完成”，不是说这个产品永远不再演进，而是说：它已经具备参考项目最重要的骨架和关键能力，成为一个真正完整的本地 AI Coding Agent。

## 版本目标
在 `1.0.0`，产品应当同时具备以下能力：
- 多入口 CLI；
- REPL 与多轮会话；
- 稳定的 QueryEngine；
- 稳定的 Agentic Loop；
- 统一 Tool Protocol；
- 只读、写入、命令执行工具链；
- 权限模型与 Plan Mode；
- 流式输出与打字机效果；
- 项目上下文系统与项目记忆；
- provider adapter 层与统一内部协议；
- 工具编排与历史记录；
- MCP / Skills / 扩展基础；
- 后台会话与恢复；
- 子 Agent 与基础协调能力；
- 上下文预算与压缩恢复；
- 完整测试、诊断和发布链路。

## 最终形态建议
### 产品形态
- 这是一个可长期使用的本地 CLI Agent；
- 既可一次性提问，也可持续多轮会话；
- 既可分析代码，也可在权限控制下修改和验证代码；
- 既可只用内建工具，也可接入 MCP / Skills 等扩展能力。

## 最终核心代码角色
### 1. Entrypoints
负责：
- 启动 CLI；
- 分发命令；
- 连接 REPL、daemon、resume、doctor 等入口。

### 2. QueryEngine
负责：
- 持有 session；
- 管理多轮会话；
- 管理权限模式；
- 管理计划状态；
- 协调上下文、工具、provider。

### 3. QueryLoop
负责：
- 跑单轮 Agentic Loop；
- 请求模型；
- 识别工具调用；
- 调用 orchestrator；
- 处理继续与终止。

### 4. Tool System
负责：
- 定义工具协议；
- 注册工具；
- 权限判断；
- 工具编排；
- 历史记录与事件反馈。

### 5. Context System
负责：
- 系统提示；
- 项目规则；
- 会话历史；
- 计划与权限状态；
- 预算、摘要与压缩。

### 6. Provider Layer
负责：
- 适配不同模型服务；
- 统一消息和事件协议；
- 统一错误模型；
- 支持流式输出。

## `1.0.0` 完成后的产品状态
- 你已经不再是在“模仿参考项目做一个小玩具”；
- 你已经做出一个与参考项目同类、结构完整、可长期演进的 CLI 产品；
- 你也已经在这个过程中真正学会了参考项目的骨架和精华。

## `1.0.0` 主要学习收获
- 学会如何设计一个本地 AI Coding Agent；
- 学会如何把会话、循环、工具、权限、上下文、provider 解耦；
- 学会如何从一个参考项目中提炼骨架，而不是只模仿表面功能；
- 学会如何从 `0.0.1` 一步步长成系统工程。

## `1.0.0` 之后先不要急着做什么
- 不急着做桌面端；
- 不急着做云服务；
- 不急着做商业化；
- 不急着做跨平台 GUI；
- 先把 CLI 产品打磨稳定，再决定下一阶段产品形态。
