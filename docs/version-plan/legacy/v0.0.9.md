# v0.0.9

## 版本定位
这是“产品体验第一次明显跃迁”的版本。

前面的版本主要搭骨架、补能力；这一版要开始把“感觉像一个真 Agent”做出来。

## 本版目标
实现：
- 流式输出；
- 打字机效果；
- 工具执行进度展示；
- REPL 中更稳定的输出渲染。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/docs/conversation/streaming.mdx`
- `claude-code-fork/src/services/api/openai/streamAdapter.ts`
- `claude-code-fork/src/services/tools/StreamingToolExecutor.ts`

本版主要学“事件流”和“状态反馈”，不追求复杂终端动画。

## 本版要做什么
### 1. Provider 层支持流式输出
新建：
- `src/llm/stream.ts`
- `src/llm/events.ts`

建议统一内部流式事件：
- `assistant_delta`
- `assistant_completed`
- `tool_call_started`
- `tool_call_completed`
- `tool_call_failed`
- `status`

### 2. CLI 输出层支持打字机效果
新建：
- `src/cli/typewriter.ts`
- `src/cli/renderStream.ts`

建议支持：
- 默认开启；
- 可通过配置关闭；
- 可以控制每次输出节奏。

### 3. REPL 支持中途状态反馈
用户需要看到：
- 模型正在思考；
- 正在调用哪个工具；
- 工具是否完成；
- 最终答案何时结束。

### 4. 输出层与 Loop 解耦
`queryLoop` 不应该直接操作终端，而是发事件；
`renderStream` 负责如何显示这些事件。

## 关键代码任务
- Provider 需要把外部 streaming 响应翻译成内部事件；
- `QueryEngine` / `queryLoop` 需要支持事件订阅；
- 工具执行器需要输出开始、结束、失败事件；
- 终端渲染要考虑换行、覆盖、长输出节流。

## 本版结束后的产品状态
- CLI 不再像“等结果的脚本”；
- 用户能实时感知系统状态；
- 打字机效果和工具进度第一次形成完整体验。

## 本版主要学习目标
- 理解流式输出的核心不是动画，而是反馈；
- 理解内部事件协议为什么能隔离 provider 和 UI；
- 学会“状态流”设计，而不是只拼字符串。

## 本版不要做什么
- 不做复杂终端组件库；
- 不做思维链可视化；
- 不做桌面端 UI；
- 不做多种渲染主题系统；
- 不做性能过早优化。
