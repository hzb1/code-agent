# v0.5.0

## 版本定位
这是“从内建工具系统走向扩展体系”的版本。

参考项目里，MCP、Skills、可扩展工具来源，不只是锦上添花，而是产品能力边界的重要扩展点。

## 本版目标
建立扩展基础，让产品支持：
- MCP 工具接入；
- Skills 读取与使用；
- 本地扩展注册。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/CLAUDE.md`
- `claude-code-fork/src/tools.ts`
- `claude-code-fork/docs/`

本版重点学“扩展接口设计”，不追求一开始就做成生态平台。

## 本版要做什么
### 1. 增加 MCP 接入层
建议新增：
- `packages/core/src/mcp/client.ts`
- `packages/core/src/mcp/types.ts`
- `packages/core/src/mcp/registry.ts`

第一版能力：
- 发现可用工具；
- 将外部工具映射为内部 Tool Protocol；
- 统一权限与执行入口。

### 2. 增加 Skills 读取层
建议新增：
- `packages/core/src/skills/loader.ts`
- `packages/core/src/skills/types.ts`
- `packages/core/src/skills/resolve.ts`

最小能力：
- 读取本地 `SKILL.md`；
- 将 skill 内容纳入上下文；
- 支持按名称引用 skill。

### 3. 扩展 Tool Registry
Registry 不再只接内建工具，而是接三类来源：
- 内建工具；
- MCP 工具；
- Skill 驱动的扩展指令。

## 建议目录形态
```text
packages/core/src/
├─ tools/
├─ mcp/
│  ├─ client.ts
│  ├─ types.ts
│  └─ registry.ts
├─ skills/
│  ├─ loader.ts
│  ├─ resolve.ts
│  └─ types.ts
└─ context/
   └─ buildContext.ts
```

## 关键代码任务
- 外部工具必须经过内部协议映射，不允许直接绕过 Tool System；
- Skills 不能只是读取原文，要有解析和注入策略；
- MCP 工具也要经过权限与日志系统；
- REPL 需要能展示“工具来源”。

## 本版结束后的产品状态
- 产品第一次具备“可扩展”能力；
- 内建能力之外，可以接入外部工具与知识；
- 与参考项目的开放式能力体系更接近。

## 本版主要学习目标
- 理解内建工具与外部工具如何统一；
- 理解为什么扩展体系必须服从同一权限和上下文规则；
- 学会给未来生态留接口，而不是一开始就做生态。

## 本版不要做什么
- 不做插件市场；
- 不做在线安装中心；
- 不做复杂权限沙箱；
- 不做远程 skill 仓库同步；
- 不做商业化扩展机制。
