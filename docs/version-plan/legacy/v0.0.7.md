# v0.0.7

## 版本定位
这是“先规划再执行”真正变成系统能力的版本。

参考项目里，Plan Mode 不是一句提示词，而是一种权限状态切换。这个版本就是把那套思想做成你自己的第一版实现。

## 本版目标
做出 `Plan Mode v1`，让产品支持：
- 在只读模式下搜索、读取、分析；
- 输出结构化计划；
- 经用户确认后再进入执行阶段。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/docs/safety/plan-mode.mdx`
- `claude-code-fork/src/QueryEngine.ts`
- `claude-code-fork/src/Tool.ts`

本版重点学“模式切换”和“只读规划”，不追求复杂审批链路。

## 本版要做什么
### 1. 在 `PermissionContext` 中增加模式字段
建议支持：
- `default`
- `plan`
- `bypass`

进入 `plan` 后：
- 只允许 `isReadOnly = true` 的工具；
- 禁止写入与命令执行；
- 允许 AI 先收集事实和形成计划。

### 2. 增加计划输出协议
新建：
- `src/app/plan.ts`
- `src/app/planTypes.ts`

建议计划结构至少包括：
- 目标；
- 观察到的事实；
- 拟修改文件；
- 风险点；
- 验证方式。

### 3. CLI / REPL 支持进入计划模式
建议支持：
- `code-agent --plan "需求"`
- REPL 中输入 `/plan` 进入计划模式；
- REPL 中输入 `/approve` 确认计划后继续执行。

### 4. QueryEngine 支持“规划阶段 -> 执行阶段”切换
`QueryEngine` 需要具备：
- 持有上一份计划；
- 记录计划是否已被批准；
- 在批准后切换权限模式。

### 5. 为后续写入工具预留挂点
即使本版还没有真正落地 `write_file`，也要在架构上保证未来能接：
- 计划输出中列出待改文件；
- 执行阶段能读取计划结果；
- 不要让计划只是一段无法被程序利用的自由文本。

## 关键代码任务
- `QueryEngine` 需要持有 `pendingPlan`；
- `queryLoop` 要能根据模式动态过滤工具列表；
- REPL 要能处理“生成计划 -> 用户确认 -> 切换执行”的链路；
- 计划输出要有结构化类型，而不是只有一段字符串。

## 本版结束后的产品状态
- 产品第一次具备“规划模式”；
- “先规划再执行”从文档要求升级为系统行为；
- 为后续危险工具接入做好了路径设计。

## 本版主要学习目标
- 理解 Plan Mode 的本质是权限切换，不是文本模板；
- 理解产品流程和工具权限必须一起设计；
- 开始学习“结构化计划”而不是“自然语言计划”。

## 本版不要做什么
- 不做复杂审批流程；
- 不做多来源权限叠加；
- 不做自动应用计划；
- 不做任务队列系统；
- 不做桌面 UI。
