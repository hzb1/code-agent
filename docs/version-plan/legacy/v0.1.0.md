# v0.1.0

## 版本定位
这是“让 Agent 真正开始理解项目”的版本。

参考项目里，系统提示、上下文组装、项目记忆，不是附属细节，而是决定 AI 能否稳定工作的核心底盘。

## 本版目标
建立第一版上下文系统，实现：
- 系统提示构建；
- 项目文档读取策略；
- 项目记忆与会话记忆；
- 将计划、工具结果、项目规则装进统一上下文。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/docs/context/system-prompt.mdx`
- `claude-code-fork/src/context.ts`
- `claude-code-fork/src/QueryEngine.ts`

本版主要学“上下文是如何被组装的”，不追求复杂压缩算法。

## 本版要做什么
### 1. 建立 Prompt 模块
新建：
- `src/prompt/system.ts`
- `src/prompt/context.ts`
- `src/prompt/rules.ts`

要解决的问题：
- 系统提示从哪里来；
- 项目规则怎么注入；
- 会话历史如何整理给模型。

### 2. 建立项目记忆模块
新建：
- `src/context/projectMemory.ts`
- `src/context/sessionMemory.ts`
- `src/context/types.ts`

建议第一版记忆内容：
- 项目定位；
- 常见入口文件；
- 已知工具限制；
- 最近读取文件摘要；
- 最近确认过的计划。

### 3. 定义文档读取优先级
建议顺序：
1. `CONSTRAINTS.md`
2. `AGENTS.md`
3. 本目录版本计划文档
4. `README.md`
5. 其他项目级文档

### 4. 将上下文构建收敛到一个入口
建议新建：`src/context/buildContext.ts`

职责：
- 收集系统规则；
- 收集项目记忆；
- 收集会话消息；
- 输出供 provider 使用的最终消息数组。

## 建议目录形态
```text
src/
├─ prompt/
│  ├─ system.ts
│  ├─ context.ts
│  └─ rules.ts
├─ context/
│  ├─ buildContext.ts
│  ├─ projectMemory.ts
│  ├─ sessionMemory.ts
│  └─ types.ts
├─ app/
│  └─ queryEngine.ts
└─ core/
   └─ message.ts
```

## 关键代码任务
- `QueryEngine` 不再手写消息拼装，而是调用 `buildContext()`；
- 读取项目文档时要有缓存，避免每轮重复读取；
- “计划结果”“权限结果”“最近工具结果”都应有单独的上下文条目，不要混成一段长文本；
- 系统提示必须可维护，不要直接散落在多个文件里。

## 本版结束后的产品状态
- AI 开始有更稳定的项目感知；
- 规则、计划、会话、工具结果第一次被统一纳入上下文系统；
- 为后续更复杂的 provider 和长会话打下基础。

## 本版主要学习目标
- 理解为什么上下文系统是 Agent 产品的底盘；
- 理解“项目规则”和“会话历史”是两种不同来源；
- 学会把杂乱信息变成结构化上下文。

## 本版不要做什么
- 不做上下文压缩算法；
- 不做 embedding / 向量检索；
- 不做远程记忆服务；
- 不做复杂知识库；
- 不做桌面同步。
