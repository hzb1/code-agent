# v0.0.1

## 版本定位
这是基线快照版本，用来记录“项目起点到底有什么、缺什么、离参考项目差多远”。

这一版不是要加新功能，而是要把起点定义清楚。

## 本版目标
确认项目已经具备的最小能力，并明确哪些能力还停留在参考项目的最外层影子阶段。

## 已有能力
- 单次 CLI 输入；
- 基础 provider 配置；
- `read_file` 工具；
- 简化版 Agent Loop；
- build / typecheck 可通过；
- 默认中文输出与详细中文注释约束。

## 目录快照
```text
src/
├─ cli/
│  └─ index.ts
├─ agent/
│  └─ runAgent.ts
├─ core/
│  ├─ config.ts
│  └─ types.ts
├─ llm/
│  └─ chatClient.ts
└─ tools/
   ├─ readFile.ts
   └─ registry.ts
```

## 对照参考仓库后，缺失的核心层
最明显缺少的是：
- 真正的 `QueryEngine`；
- 真正的 `query loop` 状态机；
- REPL 与多轮对话；
- 搜索与导航工具；
- 权限模型；
- Plan Mode；
- 流式输出；
- 项目上下文系统；
- Session 持久化；
- MCP / Skills / 扩展机制。

## 本版要沉淀的结论
### 结论 1
项目只是“参考项目核心主线”的最前端入口，不是结构对齐版。

### 结论 2
接下来不能继续在 `runAgent.ts` 上堆功能，必须先拆出骨架。

### 结论 3
后面的版本推进顺序，必须围绕：
- QueryEngine
- Query Loop
- Tool Protocol
- Permission Context
- Streaming

## 关键代码观察点
- `src/cli/index.ts`：只负责启动与输出，方向是对的；
- `src/agent/runAgent.ts`：现在承担了太多未来应该分层的职责；
- `src/tools/readFile.ts`：可以保留，但未来要挂到统一 Tool 协议下；
- `src/llm/chatClient.ts`：未来要升级成 provider adapter 层的一部分。

## 本版结束后的产品状态
- 仍然是单次 CLI；
- 仍然是只读；
- 仍然是最小产品；
- 但“起点定义”清楚了。

## 本版主要学习目标
- 看清项目的真实位置；
- 明确参考项目的骨架不是“功能列表”，而是“层次结构”。

## 本版不要做什么
- 不加新工具；
- 不改成 REPL；
- 不加流式输出；
- 不做桌面端；
- 不做大范围重写。
