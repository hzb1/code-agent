# v0.0.6

## 版本定位
这是第一个“安全系统版本”。

从这一版开始，产品不能只关注“能不能做”，还必须明确“是否允许做、何时需要确认、何时必须拒绝”。

## 本版目标
建立权限模型 v1：
- `allow`
- `ask`
- `deny`

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/docs/safety/permission-model.mdx`
- `claude-code-fork/src/Tool.ts`
- `claude-code-fork/src/utils/permissions/*`

## 本版要做什么
### 1. 新建权限模块
建议新增：
- `src/permissions/types.ts`
- `src/permissions/context.ts`
- `src/permissions/check.ts`

### 2. 定义 `PermissionContext`
第一版建议最小字段：
- `mode`
- `alwaysAllow`
- `alwaysDeny`
- `sessionAllows`
- `sessionDenies`

### 3. 在 Tool Protocol 中接入权限检查
工具开始具备：
- `isReadOnly()`
- `isDestructive()`
- `checkPermissions()`

### 4. 定义默认策略
建议：
- `read_file` / `list_files` / `search_files`：默认 `allow`
- `write_file` / `exec_command`：未来默认 `ask`
- 路径越界、危险命令：`deny`

### 5. CLI 层支持确认交互
新建：`src/cli/confirm.ts`

## 建议目录形态
```text
src/
├─ permissions/
│  ├─ types.ts
│  ├─ context.ts
│  └─ check.ts
├─ cli/
│  ├─ repl.ts
│  └─ confirm.ts
├─ tools/
│  └─ types.ts
└─ app/
   └─ queryEngine.ts
```

## 关键代码任务
- `QueryEngine` 需要持有 `permissionContext`；
- `queryLoop` 调用工具前必须经过权限判断；
- REPL 必须能处理 `ask` 结果；
- 权限结果不能只是一句字符串，要有结构化返回值。

## 本版结束后的产品状态
- 产品具备初步“安全边界”；
- 即使未来接入危险工具，也已经有权限系统承载；
- QueryEngine 开始像参考项目那样持有“会话级控制信息”。

## 本版主要学习目标
- 理解权限系统不是弹窗，而是状态与规则；
- 理解工具协议和权限协议必须配套设计。

## 本版不要做什么
- 不做 Plan Mode；
- 不做多来源权限层叠；
- 不做 denial tracking；
- 不做 auto mode；
- 不做企业策略。
