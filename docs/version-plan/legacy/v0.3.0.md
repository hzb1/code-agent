# v0.3.0

## 版本定位
这是“工具系统从能用走向成熟”的版本。

前面已经有工具协议、读写工具、命令执行、权限与流式反馈。这一版要开始补上参考项目里非常关键的一层：工具编排与执行控制。

## 本版目标
建立工具编排层，实现：
- 统一工具执行入口；
- 工具执行进度管理；
- 并发安全控制；
- 文件变更历史记录。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/services/tools/toolOrchestration.ts`
- `claude-code-fork/src/services/tools/StreamingToolExecutor.ts`
- `claude-code-fork/src/Tool.ts`

本版主要学“工具执行器”和“工具协议增强”，不追求 50+ 工具规模。

## 本版要做什么
### 1. 新建工具编排器
建议新增：
- `src/tools/orchestrator.ts`
- `src/tools/executor.ts`
- `src/tools/events.ts`

职责：
- 接收 tool call；
- 查找工具定义；
- 做权限检查；
- 执行工具；
- 发出进度和结果事件。

### 2. 支持并发安全标记
利用已有字段：
- `isConcurrencySafe`
- `isReadOnly`
- `isDestructive`

第一版可以先实现：
- 并发只允许安全的只读工具；
- 写入和命令执行一律串行。

### 3. 增加文件变更历史
建议新增：
- `src/tools/history.ts`
- `src/tools/fileSnapshot.ts`

目标：
- 记录写入前内容；
- 为后续恢复、diff、撤销做准备；
- 不依赖 git 也能做最小历史追踪。

### 4. 统一工具结果模型
工具返回值不要再五花八门，建议统一：
- `status`
- `summary`
- `payload`
- `artifacts`
- `suggestedNextStep`

## 建议目录形态
```text
src/
├─ tools/
│  ├─ orchestrator.ts
│  ├─ executor.ts
│  ├─ events.ts
│  ├─ history.ts
│  ├─ fileSnapshot.ts
│  ├─ registry.ts
│  └─ types.ts
├─ loop/
│  └─ queryLoop.ts
└─ cli/
   └─ renderStream.ts
```

## 关键代码任务
- `queryLoop` 不再自己直接执行工具，而是交给 orchestrator；
- 所有工具都要返回统一结构化结果；
- 文件写入类工具要接入历史记录；
- 并发执行要先做严格限制，避免引入竞态。

## 本版结束后的产品状态
- 工具系统第一次具备“平台感”；
- 读、写、命令执行不再是散乱函数，而是统一执行管线；
- 为后续扩展大量工具打下基础。

## 本版主要学习目标
- 理解为什么工具数量一多，就必须有 orchestration 层；
- 学会“执行器”和“工具定义”分离；
- 学会给工具结果建模，而不是靠字符串凑合。

## 本版不要做什么
- 不做多 agent 工具编排；
- 不做分布式任务；
- 不做复杂资源调度；
- 不做 git 工作树管理；
- 不做企业级审计日志。
