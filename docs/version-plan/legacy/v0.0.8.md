# v0.0.8

## 版本定位
这是产品第一次真正进入“可执行修改”的版本。

从这一版开始，系统不再只是读和分析，而是可以在用户控制下写文件、执行命令、验证结果。

## 本版目标
安全接入两类高价值工具：
- `write_file`
- `exec_command`

同时保持以下原则：
- 默认不静默执行危险操作；
- 有确认；
- 有变更预览；
- 有失败回报。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/Tool.ts`
- `claude-code-fork/src/tools.ts`
- `claude-code-fork/src/services/tools/toolOrchestration.ts`
- `claude-code-fork/docs/safety/permission-model.mdx`

本版主要学“危险工具如何安全接入”，不追求参考项目的完整工具生态。

## 本版要做什么
### 1. 新增 `write_file`
新建：`src/tools/writeFile.ts`

建议能力范围：
- 覆盖写入；
- 创建新文件；
- 支持最小 diff 预览；
- 限制只能操作项目根目录内文件。

### 2. 新增 `exec_command`
新建：`src/tools/execCommand.ts`

建议第一版只开放白名单命令，例如：
- `npm run build`
- `npm run typecheck`
- `npm test`
- `pnpm build`

必须支持：
- 超时；
- 退出码；
- stdout / stderr 摘要；
- 权限确认。

### 3. 增加变更预览能力
新建：
- `src/tools/diff.ts`
- `src/cli/preview.ts`

至少要做到：
- 写入前展示摘要；
- 展示目标文件路径；
- 显示新增、删除、修改概况。

### 4. 将危险工具挂到权限系统
本版必须把 `ask` 真正跑通：
- AI 提出写入或执行请求；
- 系统弹确认；
- 用户允许后才执行；
- 拒绝后回填结果给模型。

### 5. 将 Plan Mode 与执行能力打通
典型流程要能成立：
- 先进入计划模式；
- 得到待改文件和待执行命令；
- 用户批准；
- 再调用 `write_file` 和 `exec_command`。

## 关键代码任务
- `ToolProtocol` 要增加危险性标记；
- `exec_command` 的参数模型要清晰，不能直接接收任意 shell 文本；
- `write_file` 需要保证路径安全、内容完整写入、失败可解释；
- 被拒绝的权限结果要回填给 `queryLoop`，而不是静默中断。

## 本版结束后的产品状态
- 产品第一次具备“从规划到执行到验证”的闭环；
- 可以完成局部代码修改和本地验证；
- 与参考项目的“本地 coding agent”形态更接近一步。

## 本版主要学习目标
- 理解危险工具必须通过协议和权限系统接入；
- 理解“写代码”和“跑验证”为什么必须是同一条链路；
- 学会把命令执行结果变成模型可理解的上下文。

## 本版不要做什么
- 不开放任意 shell；
- 不做批量多文件自动覆盖；
- 不做复杂 patch DSL；
- 不做自动 git 提交；
- 不做后台任务。
