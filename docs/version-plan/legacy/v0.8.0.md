# v0.8.0

## 版本定位
这是“长会话与大上下文真正走向稳定”的版本。

前面的版本已经有上下文系统、会话、后台任务、子 Agent。到这里，最容易出问题的会变成：上下文太长、信息太散、恢复不稳定。

## 本版目标
建立高级上下文管理与恢复机制，实现：
- token budget 控制；
- 历史压缩；
- 最近文件与关键事实提炼；
- 会话恢复时的上下文重建。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/context.ts`
- `claude-code-fork/src/QueryEngine.ts`
- `claude-code-fork/docs/conversation/multi-turn.mdx`
- `claude-code-fork/docs/context/system-prompt.mdx`

本版重点学“长会话如何管理”，不追求一步到位的最优压缩算法。

## 本版要做什么
### 1. 新建上下文预算模块
建议新增：
- `packages/core/src/context/budget.ts`
- `packages/core/src/context/policy.ts`

### 2. 新建压缩与摘要模块
建议新增：
- `packages/core/src/context/compaction.ts`
- `packages/core/src/context/summary.ts`
- `packages/core/src/context/recentFiles.ts`

### 3. 定义上下文来源优先级
建议至少区分：
- 系统规则；
- 计划和权限状态；
- 最近工具结果；
- 最近文件内容；
- 历史摘要；
- 原始会话消息。

### 4. 恢复时重建上下文快照
恢复会话时不能只是把旧消息全塞回去，而是要：
- 取关键事实；
- 取最近状态；
- 取必要历史；
- 丢掉冗余噪音。

## 建议目录形态
```text
packages/core/src/context/
├─ buildContext.ts
├─ budget.ts
├─ policy.ts
├─ compaction.ts
├─ summary.ts
├─ recentFiles.ts
├─ projectMemory.ts
└─ sessionMemory.ts
```

## 关键代码任务
- `buildContext()` 要支持 budget 裁剪；
- QueryEngine 要记录关键事实而不是只依赖原始消息；
- 恢复逻辑要能重建“可工作的上下文快照”；
- 子 Agent 场景也要能复用上下文策略。

## 本版结束后的产品状态
- 长会话稳定性明显提升；
- 大项目分析更可控；
- 恢复和继续执行的可靠性开始接近成熟产品。

## 本版主要学习目标
- 理解上下文不是越多越好，而是越有组织越好；
- 理解“摘要”和“原始历史”要同时存在但扮演不同角色；
- 学会为 token budget 设计规则。

## 本版不要做什么
- 不做向量数据库平台；
- 不做全文检索服务替代品；
- 不做过度复杂的记忆图谱；
- 不做云端长期记忆产品；
- 不做花哨的可视化记忆界面。
