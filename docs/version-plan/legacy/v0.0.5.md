# v0.0.5

## 版本定位
这一版开始进入参考项目真正有“产品感”的部分：REPL 与多轮对话。

参考项目的 `QueryEngine` 价值，只有在多轮会话里才真正体现出来。

## 本版目标
让产品从“单次命令”升级为“可持续对话的 CLI Agent”。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/screens/REPL.tsx`
- `claude-code-fork/src/QueryEngine.ts`
- `claude-code-fork/docs/conversation/multi-turn.mdx`

## 本版要做什么
### 1. 新增 REPL
新建：
- `src/cli/repl.ts`
- `src/cli/output.ts`

支持：
- 持续输入；
- `exit` / `quit`；
- 清空当前会话；
- 输出历史。

### 2. 让 `QueryEngine` 持有会话消息
`QueryEngine` 从“单次调用包装器”升级为“会话持有者”。

至少持有：
- `messages`
- `cwd`
- `model`
- `readFileCache`
- `sessionId`

### 3. 增加 session storage v1
新建：
- `src/session/storage.ts`
- `src/session/serializer.ts`

第一版可以很简单：
- 保存到本地 JSON；
- 恢复最近一次会话；
- 不需要复杂 JSONL transcript。

### 4. 增加恢复命令
例如：
- `code-agent --repl`
- `code-agent --resume`

## 关键代码任务
- 把单次 CLI 与 REPL 模式统一到同一个 `QueryEngine`；
- message history 不能只保留最后一轮；
- REPL 输出层和 loop 不要耦合；
- session 恢复要保证旧消息可再次用于 loop。

## 本版结束后的产品状态
- 已经不是一次性脚本；
- 已经开始接近参考项目的“会话工具”形态；
- 可以多轮问答、连续定位、连续分析。

## 本版主要学习目标
- 理解单轮和多轮是不同层级；
- 理解为什么会话编排器必须独立存在；
- 学会最小可行的 session 持久化设计。

## 本版不要做什么
- 不做权限系统；
- 不做 Plan Mode；
- 不做写入类工具；
- 不做流式输出；
- 不做复杂 transcript 结构。
