# v0.0.3

## 版本定位
这一版专门做 `Agentic Loop v1`。

如果说 `v0.0.2` 是搭骨架，这一版就是把“智能体循环”从简化逻辑升级为真正的状态机雏形。

## 本版目标
做出一版清晰、稳定、可扩展的单轮循环，实现：
- 模型请求；
- tool call 识别；
- 工具执行；
- tool result 回填；
- 终止与继续判定。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/query.ts`
- `claude-code-fork/docs/conversation/the-loop.mdx`

不要追求参考项目的压缩、恢复、预算那一整套，只先学：
- loop state
- continue / stop
- tool result 反馈

## 本版要做什么
### 1. 明确 Loop State
新建：`src/loop/types.ts`

建议字段：
- `messages`
- `turnCount`
- `maxTurns`
- `toolContext`
- `transitionReason`
- `startedAt`

### 2. 明确终止条件
至少实现：
- 模型不再返回 tool call；
- 达到最大 turn；
- 模型返回空消息；
- 工具返回不可恢复错误。

### 3. 明确继续条件
至少实现：
- assistant 返回合法 tool call；
- 工具执行成功后回填 `tool` 消息；
- 下一轮继续带着完整历史。

### 4. 工具错误回填
不是直接崩溃，而是：
- 将错误包装为 tool result；
- 回填给模型；
- 让模型有机会修正行为。

### 5. 增加 loop 级 debug 事件
建议输出：
- `loop_start`
- `model_request`
- `tool_call_detected`
- `tool_result_received`
- `loop_continue`
- `loop_completed`

## 关键代码任务
- 将消息追加逻辑做成独立函数；
- 将 `extractToolCalls`、`parseToolArgs`、`buildToolMessage` 之类辅助函数拆开；
- 引入明确的 `maxTurns` 限制；
- 将工具执行结果统一成内部消息格式，而不是直接塞原始字符串。

## 本版结束后的产品状态
- 仍然是单次 CLI；
- 仍然只读；
- 但已经有一套像样的 `Agentic Loop v1`。

## 本版主要学习目标
- 真正理解“智能体循环”和“一次问答”的差别；
- 理解为什么工具错误应该回填而不是直接终止；
- 开始建立“状态机思维”。

## 本版不要做什么
- 不加多轮会话；
- 不做 session storage；
- 不做并发工具执行；
- 不做 token budget；
- 不做上下文压缩。
