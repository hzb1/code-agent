# v0.7.0

## 版本定位
这是“从单 Agent 迈向协同 Agent”的版本。

参考项目里，多 Agent、team、coordinator 不是一开始就该做的东西，但走到这一版时，系统已经有足够的骨架去承载更复杂的任务拆分。

## 本版目标
建立子 Agent 与协调模式的基础，实现：
- 主 Agent 规划与拆分；
- 子 Agent 执行局部任务；
- 基础工作树隔离；
- 结果汇总回主会话。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/tools.ts`
- `claude-code-fork/CLAUDE.md`
- `claude-code-fork/src/QueryEngine.ts`

本版重点学“任务拆分”和“隔离执行”，不追求完整 swarm 系统。

## 本版要做什么
### 1. 新建 Agent 管理模块
建议新增：
- `packages/core/src/agents/manager.ts`
- `packages/core/src/agents/worker.ts`
- `packages/core/src/agents/types.ts`

### 2. 支持子任务协议
建议主 Agent 传给子 Agent 的信息至少包括：
- 子任务目标；
- 可访问文件范围；
- 权限边界；
- 结果输出格式。

### 3. 增加工作树或临时目录隔离
建议新增：
- `packages/core/src/git/worktree.ts`
- `packages/core/src/git/sandbox.ts`

即使第一版不真的创建 git worktree，也要先抽象出“隔离执行环境”这个概念。

### 4. 结果汇总回主 QueryEngine
主会话需要知道：
- 哪些子任务完成；
- 哪些子任务失败；
- 汇总结果是否可继续执行下一步。

## 建议目录形态
```text
packages/core/src/
├─ agents/
│  ├─ manager.ts
│  ├─ worker.ts
│  └─ types.ts
├─ coordination/
│  ├─ planner.ts
│  └─ aggregate.ts
└─ git/
   ├─ worktree.ts
   └─ sandbox.ts
```

## 关键代码任务
- 子 Agent 也要复用同一个 QueryEngine / QueryLoop 骨架；
- 主 Agent 和子 Agent 的上下文要隔离；
- 权限模型不能因为子 Agent 引入而失效；
- 聚合结果要有结构化模型。

## 本版结束后的产品状态
- 产品开始具备“分解复杂任务”的能力；
- 会话系统第一次进入多执行体场景；
- 架构层面更接近参考项目的高级协作模式。

## 本版主要学习目标
- 理解为什么复杂任务需要拆分；
- 理解 Agent 协作的难点不是“会不会开线程”，而是上下文和权限；
- 学会给子系统做边界与汇总协议。

## 本版不要做什么
- 不做完全自动 swarm；
- 不做无人监管的并发写代码；
- 不做远程代理集群；
- 不做复杂任务看板；
- 不做团队多人实时协作。
