# v0.1.0

## 版本性质
主版本。

## 版本定位
这是正式版本线的第一版，目标不是继续堆功能，而是先把项目从“原型代码”重构成“有骨架的产品代码”。

## 本版目标
完成三件事：
- 抽出 `QueryEngine`；
- 抽出真正的 `QueryLoop`；
- 建立统一 `Tool Protocol` 和消息模型。

## 为什么先做这一版
如果不先做这一步，后面任何能力都会继续堆在：
- `src/cli/index.ts`
- `src/agent/runAgent.ts`
- `src/tools/registry.ts`

那样会直接把项目带进“功能能加，但结构越来越乱”的死路。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/entrypoints/cli.tsx`
- `claude-code-fork/src/main.tsx`
- `claude-code-fork/src/query.ts`
- `claude-code-fork/src/QueryEngine.ts`
- `claude-code-fork/src/Tool.ts`

这一版不学复杂度，只学角色拆分。

## 本版要做什么
### 1. 重构目录骨架
建议把现有 `src/` 收敛到下面结构：

```text
src/
├─ cli/
│  └─ index.ts
├─ app/
│  └─ queryEngine.ts
├─ loop/
│  ├─ queryLoop.ts
│  └─ types.ts
├─ core/
│  ├─ config.ts
│  ├─ errors.ts
│  ├─ message.ts
│  └─ types.ts
├─ llm/
│  ├─ chatClient.ts
│  └─ types.ts
└─ tools/
   ├─ readFile.ts
   ├─ registry.ts
   └─ types.ts
```

### 2. 抽出 `QueryEngine`
新建：`src/app/queryEngine.ts`

职责要明确：
- 接收用户请求；
- 管理一次调用所需的输入上下文；
- 调用 `queryLoop()`；
- 作为未来多轮会话和权限模式的承接层。

### 3. 把 `runAgent.ts` 重构成 `queryLoop.ts`
建议：
- 旧 `src/agent/runAgent.ts` 不再作为最终形态；
- 新建 `src/loop/queryLoop.ts`；
- 单轮循环只负责“模型 -> 工具 -> 结果 -> 是否继续”。

### 4. 建立统一消息类型
新建：`src/core/message.ts`

至少要有：
- `SystemMessage`
- `UserMessage`
- `AssistantMessage`
- `ToolMessage`
- `Message`

### 5. 建立统一工具协议
新建：`src/tools/types.ts`

建议字段：
- `name`
- `description`
- `inputSchema`
- `execute`
- `isReadOnly`
- `isDestructive`
- `isConcurrencySafe`

### 6. 调整 CLI 入口依赖关系
`src/cli/index.ts` 应改为：
- 解析参数；
- 初始化配置；
- 创建 `QueryEngine`；
- 调用 engine；
- 输出结果。

而不是在 CLI 里直接参与模型循环和工具执行。

## 本版结束后的产品状态
- 对用户来说，CLI 还是那个 CLI；
- 对工程来说，内部已经第一次形成正确骨架；
- 为 REPL、权限、Plan Mode、流式输出、上下文系统预留了稳定挂点。

## 是否已可用
- 可运行：是。
- 可继续堆功能：可以，但不建议直接上用户。
- 可给别人用：还不建议。

## 本版主要学习目标
- 理解 QueryEngine 和 QueryLoop 的边界；
- 理解入口层、编排层、循环层、工具层的分工；
- 学会先搭骨架再加功能。

## 本版不要做什么
- 不加 `list_files`；
- 不加 `search_files`；
- 不加 REPL；
- 不加权限系统；
- 不加流式输出；
- 不做桌面端。
