# v0.3.0

## 版本性质
主版本。

## 版本定位
这是产品第一次从“会读代码的助手”升级为“能在控制下动手做事的 Agent”。

## 本版目标
把三件事情正式做进系统：
- 权限模型；
- Plan Mode；
- `write_file` / `exec_command`。

## 为什么这三件必须同版推进
因为一旦允许 AI 写文件和执行命令，就必须同步具备：
- 权限判定；
- 规划模式；
- 用户确认；
- 失败回填。

只做其中一部分都会让产品变危险。

## 本版要做什么
### 1. 新建权限系统
新增：
- `src/permissions/types.ts`
- `src/permissions/context.ts`
- `src/permissions/check.ts`

第一版权限模型：
- `allow`
- `ask`
- `deny`

### 2. 把 Tool Protocol 接入权限字段
`src/tools/types.ts` 至少要支持：
- `isReadOnly`
- `isDestructive`
- `checkPermissions`

### 3. 新增 Plan Mode
建议支持：
- `code-agent --plan "需求"`
- REPL 中 `/plan`
- REPL 中 `/approve`

新增：
- `src/app/plan.ts`
- `src/app/planTypes.ts`

计划结构建议至少包含：
- 目标；
- 观察到的事实；
- 拟修改文件；
- 风险点；
- 验证方式。

### 4. 新增 `write_file`
新增：`src/tools/writeFile.ts`

第一版职责：
- 在项目内安全写入文件；
- 展示最小变更预览；
- 支持覆盖和新建；
- 失败要有清晰错误提示。

### 5. 新增 `exec_command`
新增：`src/tools/execCommand.ts`

第一版要求：
- 只支持白名单命令；
- 有超时；
- 有退出码；
- 有 stdout/stderr 摘要；
- 结果能回填给模型。

### 6. 增加确认与预览层
新增：
- `src/cli/confirm.ts`
- `src/cli/preview.ts`
- `src/tools/diff.ts`

## 本版结束后的产品状态
- 产品第一次具备“先规划，再执行，再验证”的完整闭环；
- AI 不再只是会解释代码，也能在许可范围内改代码和跑命令；
- 已经进入真正的本地 coding agent 阶段。

## 是否已可用
- 对你自己：已可用，但还需要稳定化。
- 对别人：还不建议直接给。

## 本版主要学习目标
- 理解为什么权限、Plan、执行工具必须一起设计；
- 学会把危险能力接入协议化系统；
- 学会将“用户批准”做成系统流程，而不是一句提示词。

## 本版不要做什么
- 不加流式输出；
- 不做复杂 provider 兼容层；
- 不做后台会话；
- 不做子 Agent；
- 不做桌面端。
