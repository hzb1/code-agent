# v0.2.0

## 版本性质
主版本。

## 版本定位
这是产品第一次从“单次问答原型”升级为“可持续对话的只读代码助手”。

## 本版目标
一次性补齐三组最关键的只读能力：
- 项目检索工具；
- REPL；
- 多轮会话与会话恢复。

## 为什么这一版要把这些放在一起
因为只读代码助手真正可用，至少要同时满足：
- 能找文件；
- 能持续追问；
- 能保留历史；
- 能恢复会话。

如果只做其中一项，用户仍然会觉得它只是一个“命令行问答脚本”。

## 对齐参考仓库的重点
重点参考：
- `claude-code-fork/src/screens/REPL.tsx`
- `claude-code-fork/src/QueryEngine.ts`
- `claude-code-fork/docs/conversation/multi-turn.mdx`
- `claude-code-fork/src/tools.ts`

## 本版要做什么
### 1. 增加检索工具组
新增：
- `src/tools/listFiles.ts`
- `src/tools/searchFiles.ts`

工具职责：
- `list_files`：列目录与结构；
- `search_files`：按关键词找候选文件；
- `read_file`：读取具体文件内容。

这三个工具要能组合成：
- 先列目录；
- 再搜索关键词；
- 再读目标文件；
- 最后基于证据回答。

### 2. 新增 REPL
新增：
- `src/cli/repl.ts`
- `src/cli/output.ts`

至少支持：
- 持续输入；
- `exit` / `quit`；
- `clear`；
- 打印最近对话结果。

### 3. 让 QueryEngine 真正持有会话
`src/app/queryEngine.ts` 至少要持有：
- `messages`
- `sessionId`
- `cwd`
- `model`
- `toolRegistry`
- `readOnlyCache`

### 4. 增加 Session Storage v1
新增：
- `src/session/storage.ts`
- `src/session/serializer.ts`
- `src/session/cache.ts`

第一版即可：
- 存本地 JSON；
- 恢复最近一次会话；
- 不追求复杂 transcript 格式。

### 5. 增加基础 `doctor`
新增：`src/cli/doctor.ts`

至少检查：
- `LLM_*` 配置是否完整；
- provider / base URL / model 是否合理；
- cwd 是否有效；
- 常见网络错误、429、超时建议。

## 详细开发任务清单
为了避免 `v0.2.0` 停留在“版本说明”，这一版直接按工作包推进。

### 工作包 1：只读检索工具组
目标：
- 让产品从“只能读取已知文件”升级为“能先找，再读，再回答”。

要新增的文件：
- `src/tools/listFiles.ts`
- `src/tools/searchFiles.ts`

要修改的文件：
- `src/tools/registry.ts`
- `src/tools/types.ts`
- `src/app/queryEngine.ts`

具体做什么：
- 新增 `list_files`
- 新增 `search_files`
- 继续复用 `read_file`
- 在 registry 中注册三件套：`list_files + search_files + read_file`

实现要求：
- `list_files` 支持目录列举、深度限制、忽略噪音目录
- `search_files` 先做文件名/路径级搜索，不在这一版提前做全文 grep
- 两个工具都必须遵守项目根目录边界与结果数量上限

本工作包完成后，至少要能支持：
- “入口文件在哪”
- “有哪些 cli 文件”
- “帮我找 queryLoop 在哪”

### 工作包 2：QueryEngine 会话化
目标：
- 让 `QueryEngine` 从“一次请求编排器”升级为“一个 session 的编排器”。

要修改的文件：
- `src/app/queryEngine.ts`
- `src/core/message.ts`
- `src/loop/types.ts`

建议新增的文件：
- `src/session/types.ts`

具体做什么：
- 让 `QueryEngine` 实例持有 `messages`
- 增加 `sessionId`
- 持有 `cwd`
- 持有 `toolRegistry`
- 增加最小 `readOnlyCache`

建议增加的方法：
- `runOnce(prompt: string)`
- `getMessages()`
- `clearMessages()`
- `getSessionState()`

设计取舍：
- 这一版先不引入流式 `AsyncGenerator`
- 这一版先不引入复杂会话状态机
- 目标只是先把“多轮状态挂在 QueryEngine 上”这件事做对

### 工作包 3：REPL
目标：
- 把 CLI 从“单次命令”升级为“持续对话”。

要新增的文件：
- `src/cli/repl.ts`
- `src/cli/output.ts`

要修改的文件：
- `src/cli/index.ts`

具体做什么：
- 新增 REPL 启动入口
- 循环读取用户输入
- 复用同一个 `QueryEngine` 实例持续对话
- 统一输出普通答案、错误、系统提示

最小支持命令：
- `exit`
- `quit`
- `clear`
- `/help`
- `/session`

这一版先不要做：
- 快捷键体系
- 输入历史搜索
- 流式逐字渲染
- transcript UI

### 工作包 4：Session Storage v1
目标：
- 让多轮会话跨进程可恢复，但先做最小实现。

要新增的文件：
- `src/session/storage.ts`
- `src/session/serializer.ts`
- `src/session/cache.ts`
- `src/session/types.ts`

要修改的文件：
- `src/app/queryEngine.ts`
- `src/cli/repl.ts`

具体做什么：
- 定义最小会话存储结构
- 保存最近一次会话
- 支持恢复最近一次会话
- 会话损坏时给出清晰提示

第一版建议的数据结构至少包含：
- `sessionId`
- `createdAt`
- `updatedAt`
- `cwd`
- `model`
- `messages`

设计取舍：
- 先用普通 JSON，不做 JSONL transcript
- 不做消息级增量写入
- 不做成本追踪
- 不做文件快照回滚

### 工作包 5：doctor
目标：
- 给 `v0.2.0` 增加一个最小排障入口。

要新增的文件：
- `src/cli/doctor.ts`

要修改的文件：
- `src/cli/index.ts`
- `src/core/config.ts`

具体做什么：
- 检查 `LLM_*` 配置
- 检查当前工作目录
- 检查 provider / base URL / model 组合是否合理
- 输出常见错误的中文建议

第一版先只做：
- 静态检查
- 配置诊断
- 排障建议

这一版先不要做：
- 真实联网探测
- provider 连通性 ping
- 复杂系统体检

### 工作包 6：测试与文档收口
目标：
- 确保 `v0.2.0` 不只是功能存在，而是能被验证和继续演进。

建议新增测试：

重点验证内容：
- `list_files` 能列目录且遵守边界
- `search_files` 能返回合理候选文件
- QueryEngine 能保留连续两轮消息
- REPL 支持 `exit / clear`
- Session Storage 能保存并恢复最近会话
- doctor 能输出可操作的中文诊断结果

文档要同步更新：
- `README.md`

## 建议开发顺序
建议按下面顺序推进，不要乱序开工：

1. `listFiles + searchFiles + registry`
2. `QueryEngine 会话状态`
3. `REPL`
4. `Session Storage`
5. `doctor`
6. `tests + README + 版本文档`

这样安排的原因：
- 先把“找代码”的能力立起来，产品提升最直接
- 再把状态挂到 `QueryEngine`
- 然后给状态加交互壳
- 最后补恢复与诊断

## 第一刀建议
如果准备正式开工，最推荐的第一刀是：

1. 新建 `src/tools/listFiles.ts`
2. 新建 `src/tools/searchFiles.ts`
3. 修改 `src/tools/registry.ts`

原因：
- 不会先打乱当前骨架
- 回报最大
- 立刻让产品从“只能读已知文件”升级到“能找代码”

## 本版结束后的产品状态
- 产品第一次具备真正的“项目级只读理解能力”；
- 你可以连续追问，而不必每次重新输入背景；
- 结构上也开始出现参考项目那种“会话工具”的感觉。

## 是否已可用
- 对开发者：可用。
- 对最终用户：可以开始内测，但还不稳定。

## 本版主要学习目标
- 理解多轮会话和单轮 Loop 的关系；
- 理解只读工具组为什么是第一批最重要的工具；
- 学会最小可行的 REPL 和会话持久化设计。

## 本版能学到的技术点
- 如何设计 `list_files + search_files + read_file` 这种可组合的只读工具链；
- 如何在 Node.js CLI 里实现最小可用的 REPL、命令解析和交互输出；
- 如何把会话状态从一次调用提升到可持续持有的 Session 模型；
- 如何做本地 JSON 持久化、序列化和恢复，支撑多轮会话；
- 如何为 CLI 增加 `doctor` 诊断入口，把排障能力做成产品功能。

## 本版不要做什么
- 不加写文件；
- 不加命令执行；
- 不加权限弹窗；
- 不加 Plan Mode；
- 不加流式输出。
