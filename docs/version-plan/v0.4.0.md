# v0.4.0

## 版本性质
主版本。

## 版本定位
这是产品第一次明显有“真实 Agent 体验”的版本。

前面的版本已经能规划、执行、验证，但在体验和推理稳定性上，还缺两块核心底盘：
- 流式反馈；
- 上下文系统。

## 本版目标
把三件事情正式做起来：
- 流式输出；
- 打字机效果；
- 系统提示、项目规则、项目记忆、会话记忆组成的上下文系统。

## 为什么这一版重要
如果没有流式反馈，用户会觉得产品“卡住了”；
如果没有上下文系统，产品会出现：
- 多轮对话越聊越散；
- 规则无法稳定生效；
- 项目记忆无法复用；
- 计划和执行之间断裂。

## 本版要做什么
### 1. 建立内部流式事件协议
新增：
- `src/llm/stream.ts`
- `src/llm/events.ts`
- `src/loop/events.ts`

建议统一事件：
- `assistant_delta`
- `assistant_completed`
- `tool_call_started`
- `tool_call_completed`
- `tool_call_failed`
- `status`

### 2. 新增终端流式渲染层
新增：
- `src/cli/renderStream.ts`
- `src/cli/typewriter.ts`

要求：
- 打字机效果可开关；
- REPL 与单次 CLI 共用同一套渲染逻辑；
- `queryLoop` 不直接操作终端输出。

### 3. 建立 Prompt 与 Context 模块
新增：
- `src/prompt/system.ts`
- `src/prompt/context.ts`
- `src/prompt/rules.ts`
- `src/context/buildContext.ts`
- `src/context/projectMemory.ts`
- `src/context/sessionMemory.ts`
- `src/context/types.ts`

### 4. 定义文档与规则装配顺序
建议顺序：
1. `CONSTRAINTS.md`
2. `AGENTS.md`
3. 版本计划文档
4. `README.md`
5. 项目内其他说明文档

### 5. 让 QueryEngine 不再自己拼消息
`src/app/queryEngine.ts` 需要改成：
- 收集当前会话；
- 收集项目规则；
- 收集最近计划和权限状态；
- 调用 `buildContext()` 产出最终消息数组。

## 本版结束后的产品状态
- 产品第一次具有“实时感”；
- 上下文不再只是临时拼接，而是开始成为稳定系统；
- 多轮对话、计划、执行、记忆开始形成统一体验。

## 是否已可用
- 对你自己：已基本可用。
- 对别人：可以开始更认真地试用，但还需要稳定化。

## 本版主要学习目标
- 理解事件流为什么是体验系统的底盘；
- 理解上下文系统为什么是 Agent 产品的底盘；
- 学会把“规则、历史、计划、记忆”统一成一个可维护的 context pipeline。

## 本版不要做什么
- 不做 provider 适配层重构；
- 不做工具编排层；
- 不做 MCP / Skills；
- 不做后台会话；
- 不做子 Agent。
