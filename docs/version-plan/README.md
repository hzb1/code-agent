# Version Plan

## 说明
这套文档是本项目新的正式版本计划。

它解决 4 个问题：
- 版本不要拆得过碎；
- 中途必须出现“已经可用”的产品版本；
- 版本路线要覆盖参考项目的核心功能与核心知识点；
- 旧计划如果粒度或方向不够好，可以重构，不强行继承。

参考仓库：
- `claude-code-fork/src/entrypoints/cli.tsx`
- `claude-code-fork/src/main.tsx`
- `claude-code-fork/src/query.ts`
- `claude-code-fork/src/QueryEngine.ts`
- `claude-code-fork/src/Tool.ts`
- `claude-code-fork/src/tools.ts`
- `claude-code-fork/src/context.ts`
- `claude-code-fork/src/services/api/openai/*`
- `claude-code-fork/docs/`

## 版本策略
### 1. 起点版本
新的逻辑起点版本定义为：`0.1.0`

含义是：
- `0.0.x` 不再作为主线版本；
- 现有代码基线可以直接视为“进入正式规划前的原型”；
- 新版本线从 `0.1.0` 开始，方便表达“已经进入可演进产品阶段”。

### 2. 版本号语义
- `0.x.0`：增加一组新的核心能力，属于主版本推进。
- `0.x.1`：不增加新的产品能力边界，只做稳定化、测试、重构、错误处理、文档收口、交互优化。
- `1.0.0`：完成参考项目核心骨架与核心能力覆盖，达到“同类 CLI 产品完成版”。

### 3. 补丁版本原则
补丁版本必须遵守：
- 不新增新的能力边界；
- 不新增新的大模块；
- 只修正上一版已经引入的能力；
- 只提升稳定性、可维护性和可交付性。

## 可用里程碑
这条路线不是到 `1.0.0` 才第一次能用，而是分层次变得可用：

1. `v0.2.1`
定位：只读可用版。
含义：已经可以给人用于“理解代码库、找文件、做项目问答”。

2. `v0.3.1`
定位：安全改动可用版。
含义：已经可以在人工确认下做局部改代码、跑命令、回报结果。

3. `v0.4.1`
定位：个人主力可用版。
含义：已经具备多轮对话、规划、执行、流式反馈、项目上下文，能作为你自己的日常 CLI Agent。

4. `v0.9.0`
定位：发布候选版。
含义：工程化、测试、诊断、发布链路成熟，已经可以作为稳定产品对外试用。

5. `v1.0.0`
定位：参考项目同类 CLI 产品完成版。
含义：核心骨架、核心功能、核心知识点全部覆盖完成。

## 覆盖承诺
这套路线的目标不是“看起来像参考项目”，而是确保你走完整条路线后：
- 真的学会参考项目最重要的架构与设计思想；
- 真的做出一个完整可用的本地 CLI Coding Agent；
- 真的具备继续向 Codex / Claude Code 同类产品演进的能力。

详细覆盖矩阵见：
- [COVERAGE.md](./COVERAGE.md)

另外，这套正式版本文档不只说明“每版做什么”，也要求明确写出：
- 每个版本要解决的产品问题；
- 每个版本要落地的代码结构与模块边界；
- 每个版本能学到的具体技术点。

## 版本总览
1. `v0.1.0`：架构骨架与单轮 Loop
2. `v0.1.1`：骨架稳固版
3. `v0.2.0`：检索工具、REPL、多轮会话
4. `v0.2.1`：只读可用版
5. `v0.3.0`：权限、Plan Mode、写入与命令执行
6. `v0.3.1`：安全改动可用版
7. `v0.4.0`：流式输出、上下文系统、项目记忆
8. `v0.4.1`：个人主力可用版
9. `v0.5.0`：Provider 适配层、工具编排、历史记录
10. `v0.6.0`：Core 抽离、MCP、Skills、扩展基础
11. `v0.7.0`：后台会话、守护进程、恢复
12. `v0.8.0`：子 Agent、工作树隔离、高级上下文管理
13. `v0.9.0`：观测、测试、诊断、发布工程
14. `v1.0.0`：同类 CLI 产品完成版
