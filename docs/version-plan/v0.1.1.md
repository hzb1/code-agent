# v0.1.1

> 学习基线说明：旧实现的完成记录仅保留为历史背景，不代表当前工作树状态。完成 `v0.1.0` 的学习验收后再进入本版本。

## 版本性质
补丁版本。

## 版本定位
这是骨架稳固版，不增加新的能力边界，只把 `v0.1.0` 建出来的骨架打牢。

## 本版目标
让 `v0.1.0` 从“结构初步正确”提升到“结构稳定、便于继续开发”。

## 补丁版本约束
这一版不允许新增以下能力：
- 新工具种类；
- REPL；
- 多轮会话；
- 权限系统；
- 流式输出。

## 本版要做什么
### 1. 稳定消息与工具类型
收口：
- `src/core/message.ts`
- `src/tools/types.ts`
- `src/llm/types.ts`

目标：
- 类型名稳定；
- 字段语义稳定；
- 不再频繁改接口。

### 2. 增加骨架级调试事件
建议在 `queryLoop` 和 `QueryEngine` 增加：
- `loop_start`
- `model_request`
- `tool_call_detected`
- `loop_continue`
- `loop_completed`

这仍然属于稳定性与可观测性，不属于新产品功能。

同时允许增加最小调试与测试注入挂点，例如：
- `onDebugEvent`
- `queryLoopRunner`
- `createChatCompletionFn`

这些挂点的目的不是扩展产品能力，而是：
- 让测试不依赖真实网络；
- 让骨架调试输出可被上层接管；
- 为后续版本继续演进保留稳定注入点。

### 3. 补基础 smoke 测试
建议使用 `node:test` 作为本版测试基线（轻量、原生、依赖最少）。

建议新增：
- `tests/unit/queryLoop.test.ts`
- `tests/unit/queryEngine.test.ts`
- `tests/integration/readOnlyCli.test.ts`

其中集成测试允许采用：
- 真 CLI 启动；
- 假 Provider 响应；
- 真只读工具执行；

用来验证“入口 -> Engine -> Loop -> Tool -> 最终答案”这条骨架链路。

### 4. 收口错误类型
建议新增：
- `ConfigError`
- `ProviderError`
- `ToolExecutionError`
- `LoopTerminatedError`

### 5. 收口文档
要求：
- `AGENTS.md`
- `CONSTRAINTS.md`
- `docs/version-plan/*`

对当前骨架描述一致，不要出现文档和代码角色打架。

### 6. 补最小交互与排障增强
这一版允许补充一些不改变能力边界的 CLI 体验增强，例如：
- 默认在 `stderr` 打印简短的对话过程日志；
- 允许通过 `CA_SHOW_CHAT_TRACE=0` 关闭过程日志；
- 允许通过 `LLM_DEBUG_HTTP=1` 打印请求/响应摘要；

这些增强属于：
- 交互优化；
- 可诊断性增强；

不应被理解为：
- REPL；
- 多轮对话；
- 流式输出；
- 新的产品能力边界。

## 本版主要学习目标
- 理解为什么补丁版本不该继续加新能力；
- 学会用测试和错误模型稳住架构；
- 学会在“重构期”控制接口漂移。

## 本版能学到的技术点
- 如何收口 TypeScript 类型接口，减少重构期字段和命名反复漂移；
- 如何设计结构化错误模型，把配置错误、Provider 错误、工具错误分层表达；
- 如何给 QueryEngine 和 QueryLoop 加调试事件，建立最小可观测性；
- 如何为新骨架补 smoke test，让后续重构有回归抓手；
- 如何通过测试注入点和可关闭日志，在不新增能力边界的前提下提升可测性与可诊断性；
- 如何用补丁版本做稳定化，而不是继续透支新能力。

## 本版实际已补充的内容
除了原始计划里的“类型、错误、测试、调试事件”之外，当前实现还额外补了几项仍属于补丁版范围的内容：

1. CLI 过程日志
- 默认在 `stderr` 打印模型决策、工具调用和完成摘要；
- 可通过 `CA_SHOW_CHAT_TRACE=0` 关闭；
- 目的：提升骨架阶段的过程可见性，而不是提前实现 REPL。

2. HTTP 调试摘要
- 可通过 `LLM_DEBUG_HTTP=1` 打印 Request / Response 摘要；
- 目的：帮助排查 provider 请求问题；
- 这属于排障能力，不属于新产品功能。

3. 测试注入挂点
- `QueryEngine` 支持注入 `queryLoopRunner`；
- `QueryLoop` 支持注入 `createChatCompletionFn`；
- 调试事件支持 `onDebugEvent`；
- 目的：让单测和集成测试不依赖真实网络和真实上游模型。

## 本版不要做什么
- 不新增任何产品能力边界；
- 不改目录方向；
- 不补 REPL；
- 不补搜索工具；
- 不补流式输出。
