# v0.2.1

## 版本性质
补丁版本。

## 版本定位
这是第一版“可以给人试用”的版本，但范围仍然只限于：
- 只读代码理解；
- 项目结构定位；
- 多轮追问；
- 最近会话恢复；
- 基础自检和排障。

## 本版目标
不增加新的产品能力，只把 `v0.2.0` 已经引入的只读链路收口到“稳定可试用”。

## 当前执行进度（2026-04-23）
- [x] 工作包 1：只读工具结果质量收口
- [x] 工作包 2：REPL 与恢复链路稳定化
- [x] 工作包 3：doctor 与错误提示收口
- [x] 工作包 4：测试与文档收口
- [x] 工作包 5：关键注释与教学性收口

当前验证结果：
- `npm run build` 通过
- `npm run typecheck` 通过
- `npm run lint` 通过
- `npm test` 通过（受沙箱限制，涉及本地端口监听的用例会自动 `skip`）
- 手动命令验证通过：`ca doctor`、`ca`（进入 REPL 并 `exit`）

## 为什么这一版必须单独做
`v0.2.0` 已经把关键能力边界补齐了：
- 检索工具组；
- REPL（持续聊天模式）；
- QueryEngine（会话编排器）；
- Session Storage（恢复最近会话）；
- doctor（自检和排障）。

如果这时直接进入 `v0.3.0` 去加写文件、命令执行和权限系统，就会把一套还不够稳的只读基础带进更危险的执行阶段。

所以 `v0.2.1` 的任务很明确：
- 只读结果质量先稳；
- REPL 交互先稳；
- 会话恢复先稳；
- doctor 文案先稳；
- 关键代码注释先补齐；
- 测试与文档先补齐。

## 本版要做什么
### 1. 稳定检索结果质量
优化：
- `list_files` 的忽略规则、深度与结果可读性；
- `search_files` 的排序、候选数量与结果稳定性；
- `read_file` 的截断提示、文件不存在提示、非法路径提示。

### 2. 稳定 REPL 交互
优化：
- 空输入处理；
- `Ctrl+C` / EOF / readline 异常处理；
- 错误不退出整个 REPL；
- 恢复最近会话后的 `/last`、连续追问、退出保存稳定性。

### 3. 稳定 Session Storage
要求：
- 最近一次会话可恢复；
- 恢复后历史能继续参与回答；
- 会话文件损坏时给出清晰提示；
- 运行时生成的 `.code-agent/` 目录不污染仓库。

### 4. 收口 doctor 与错误提示
要求：
- 错误提示统一用中文；
- 文案要可操作；
- 能明确区分配置问题、模型权限问题、网络问题、限流问题、工具问题。

### 5. 增加只读回归测试
建议至少覆盖：
- “入口文件在哪”；
- “这个项目做什么”；
- “帮我找某个关键词在哪”；
- REPL 连续两轮追问；
- 恢复最近会话后继续提问；
- doctor 配置异常提示。

### 6. 收口关键模块注释
要求：
- 注释优先解释“为什么这样做”，不是只翻译代码表面行为；
- 关键模块要写清职责边界、状态流向和风险点；
- 注释要服务于“阅读理解和学习”，让第一次读代码的人能跟得上。

## 详细开发任务清单
为了避免 `v0.2.1` 变成“只说要稳定”的空文档，这一版直接按工作包推进。

### 工作包 1：只读工具结果质量收口
目标：
- 让“先找，再读，再回答”的只读链路更稳定，减少噪音结果和误导性提示。

要修改的文件：
- `src/tools/listFiles.ts`
- `src/tools/searchFiles.ts`
- `src/tools/readFile.ts`

可以修改的关联文件：
- `src/tools/registry.ts`
- `tests/unit/listFiles.test.ts`
- `tests/unit/searchFiles.test.ts`

具体做什么：
- 调整默认忽略规则，减少对只读分析价值低的目录噪音；
- 稳定 `search_files` 的排序和截断策略，避免结果“很多但不准”；
- 为 `read_file` 增加更可读的截断说明与错误提示；
- 保持项目边界校验，不削弱安全约束。

完成标准：
- 模型更稳定地回答“入口文件在哪”“queryLoop 在哪”“有哪些 cli 文件”；
- 工具异常时，用户能从错误文案里知道下一步该怎么做。

### 工作包 2：REPL 与恢复链路稳定化
目标：
- 让 REPL 在真实使用中更抗异常，而不是“一报错就退出”。

要修改的文件：
- `src/cli/repl.ts`
- `src/cli/index.ts`
- `src/app/queryEngine.ts`
- `src/session/storage.ts`

建议新增或修改测试：
- `tests/unit/repl.test.ts`
- `tests/integration/sessionResume.test.ts`
- `tests/e2e/readOnlyRepl.test.ts`

具体做什么：
- 处理 `Ctrl+C`、EOF、readline 抛错等中断场景；
- 确保 REPL 内错误不会直接导致整个进程退出；
- 校验恢复最近会话后，历史消息能继续参与后续回答；
- 校验 `/last`、`clear`、`exit` 和恢复状态之间的关系是否正确。

完成标准：
- 连续两轮追问稳定；
- 退出后重新进入同目录，最近会话可恢复；
- 恢复后继续提问，不会丢历史；
- 会话损坏时只提示，不崩溃。

### 工作包 3：doctor 与错误提示收口
目标：
- 把报错从“原始异常”升级为“用户可直接采取动作的提示”。

要修改的文件：
- `src/cli/doctor.ts`
- `src/llm/chatClient.ts`
- `src/core/config.ts`

建议新增或修改测试：
- `tests/integration/doctor.test.ts`

具体做什么：
- 细分 `403 / 404 / 429 / 超时 / DNS / 非 JSON 响应` 的提示；
- 明确哪些是配置问题，哪些是 provider/model 权限问题；
- `doctor` 保持静态诊断，不提前做真实联网探测；
- 收口提示用语，避免同类问题在不同入口下文案差异过大。

完成标准：
- 用户看到错误后，能判断是该改 `.env`、换模型、检查权限还是检查网络；
- doctor 输出继续保持中文、可操作、适合复制粘贴排障。

### 工作包 4：测试与文档收口
目标：
- 确保 `v0.2.1` 真正达到“只读可用版”，而不只是主观感觉更稳。

建议新增测试：
- `tests/unit/readFile.test.ts`
- `tests/integration/searchAndRead.test.ts`
- `tests/integration/sessionResume.test.ts`
- `tests/e2e/readOnlyRepl.test.ts`

要修改的文档：
- `README.md`
- `docs/version-plan/v0.2.1.md`

具体做什么：
- 用真实命令链路覆盖“查找 -> 读取 -> 回答”；
- 增加 REPL 连续追问与恢复最近会话的回归测试；
- README 明确“只读可用版”范围、常见错误与推荐用法；
- 补齐会话目录忽略等工程收口项。

完成标准：
- `npm run build`
- `npm run typecheck`
- `npm run lint`
- `npm test`
- 关键命令手动可跑：`ca`、`ca doctor`

### 工作包 5：关键注释与教学性收口
目标：
- 让 `v0.2.1` 不只是“能用”，也更适合阅读、理解和学习。

要修改的文件：
- `src/app/queryEngine.ts`
- `src/cli/repl.ts`
- `src/session/storage.ts`
- `src/session/serializer.ts`
- `src/tools/listFiles.ts`
- `src/tools/searchFiles.ts`
- `src/tools/readFile.ts`

具体做什么：
- 为关键函数补“职责 / 设计原因 / 状态流向 / 风险点”注释；
- 对恢复最近会话、REPL 控制流、工具边界校验等高理解成本逻辑补教学型注释；
- 避免低价值注释，不写“变量赋值”这类表面描述；
- 注释统一用中文，并在首次出现时保留必要英文术语说明。

完成标准：
- 新读者能顺着注释读懂 QueryEngine、REPL、Session Storage 和只读工具主链路；
- 关键模块里高理解成本逻辑都有“为什么这样做”的解释；
- 注释不明显啰嗦，也不与实现脱节。

## 建议开发顺序
建议按下面顺序推进，不要乱序开工：

1. 只读工具结果质量
2. REPL 与恢复链路
3. doctor 与错误提示
4. 测试与文档收口
5. 关键注释与教学性收口

这样安排的原因：
- 先把“答案质量基础”稳住；
- 再把持续聊天和恢复链路稳住；
- 然后统一错误提示；
- 再用测试和文档把这版收口；
- 最后集中补关键注释，避免在代码还没稳定时反复改注释。

## 本版主要学习目标
- 理解“可用”不只是功能存在，而是交互稳定、提示清楚、回归可测；
- 学会给一个只读产品做第一轮稳定化收口；
- 学会写真正服务阅读和教学的工程注释；
- 学会把补丁版本用在体验、测试和错误处理上。

## 本版能学到的技术点
- 如何优化文件搜索结果质量，包括忽略规则、排序和截断提示；
- 如何让 REPL 在空输入、中断、工具失败后仍能维持稳定交互；
- 如何处理 Session Storage 损坏、恢复失败和恢复后继续追问；
- 如何为只读产品写 integration/e2e 测试，覆盖真实问答与连续追问；
- 如何给关键模块补“职责、边界、设计原因、风险点”四类高价值注释；
- 如何把错误提示从“异常文本”提升为“用户能直接执行的诊断文案”。

## 本版不要做什么
- 不新增新工具；
- 不加写文件；
- 不加命令执行；
- 不加权限系统；
- 不加 Plan Mode；
- 不加流式输出；
- 不提前引入重型 transcript / resume picker / 会话列表体系。
